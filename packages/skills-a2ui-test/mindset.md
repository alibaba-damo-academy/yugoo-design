# A2UI 自动面板测试 Mindset

<design_skills>

## probe_questions

记录一个小型测试场景的真实问题与答案，验证没有预定义面板时的生成式面板是否可用。

## probe_records

用借鉴 Web App 功能模块的数据形态验证自动面板的功能卡编辑与保存，不依赖问题清单字段。

## probe_report

用嵌套 JSON 与 Markdown 产物验证可读布局和同 Bundle 文件预览。

</design_skills>

## 目标与边界

本 Kit 只检验系统级 `presentation.mode: auto` 的多种数据形态。它不提供某行业的方法论，也不要求其它 Kit、外部数据或求解器。设计文件仍是唯一事实；生成的 A2UI 视图是可重建缓存，不是新的 Bundle 产物。

从用户给出的一个具体小场景开始，保存少量有意义的测试问题，先让用户在面板中作答，再检验保存、重开和修改后重生成。问题可以是文本或单选；推荐选项不是用户答案。没有证据时保持空答案，不能为了让测试“看起来完成”而编造回答。

最小闭环：创建项目并选用此 Kit → 生成 `probe_questions` 状态 → 自动面板出现 → 用户修改答案并保存 → 重开后答案仍来自设计文件。若生成器不可用，清楚展示只读回退，不声称测试成功。GRA/KAG 不作为面板生成前置条件。

只修订本次测试涉及的问题，保留稳定 key 和既有答案。保存通知已给出差异时不重复应用；变更设计文件后应等待新视图生成，旧视图不可继续保存。测试完成后无需把本 Kit 的示例或缓存迁入正式设计项目。
