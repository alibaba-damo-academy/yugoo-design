# 面向用户的切片名称

<!-- 作者说明：以下结构是作者起点，不要求照抄标题或拆出正向/还原两章。内部 name 是稳定 ID，正文标题是可读名称；现有方法先建立保留映射再重组，不删其原则和专业判断。 -->

## 输入与输出入口

指定 canonical 路径和本 Bundle 可读输出契约；资源路径按实际宿主绑定解析。
说明首次生成/已存在状态的最小读取范围，示例不是当前用户事实。
说明当前请求为何适用、哪些相邻职责不属于这里。区分用户事实、直接证据、外部参考、假设与未知；按本领域解释需要读什么以及它支持何种判断。

## 专业方法

写本领域实质判断、必要的用户互动和证据选择；不要只列“分析、生成、校验”。
给出如何从证据得到设计、怎样选择粒度、比较方案及处理例外。输出契约规定表示方式，不代替这些方法。
说明同一方法在首次设计、还原与局部修订中的证据差异：设计可提出待确认方案；还原忠实恢复有证据的产品而非自行优化。无需人为拆成两个章节。
将两条执行入口共用的关键事实/推断边界、所有权、稳定 ID 与来源约束放入 Bundle 可达资源；当前显式还原执行不注入本正文，不得只靠作者规范或正文链接声称已注入。

## 修订与产物

保持稳定 ID 与未改记录；保存 diff 不重放。按实际依赖判断参数变更是否影响已有产物。
有 Worker/脚本/外部工具时说明具体输入、输出、权限、真实成功证据及失败后的有限退路。
不把缺少某个上游 Bundle 当成必须启动所有切片的理由；不把局部修订变成全量重建，也不覆盖用户明确保留的事实和范围。

## 校验与交接

给出当前宿主可执行的校验/发布入口与 manifest handoff；原工作副本修复失败，不伪报成功。
向主对话报告本轮事实、文件、用户应关注的内容和未决范围；不新增后台审查或评分规则。
