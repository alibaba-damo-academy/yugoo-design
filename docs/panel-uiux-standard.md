# Panel UIUX 规范

面向 Bundle 作者、A2UI/DSL 作者、共享组件开发者和审阅 Agent。目标是让用户更容易理解、判断和修改设计，而不是让每个面板长成同一个表单。本文是视觉与交互的统一作者入口，不新增 DSL 字段、业务数据、权限、评分或审批流程。

## 规范如何生效

- **表达规则**：本文定义信息表达、层级和交互质量。作者按场景选择，不复制 Web App 的业务字段和工作流程。
- **能力契约**：[DSL](dsl-spec.md)、[组件目录](../packages/core/src/panel-component-catalog.ts)及实际校验器决定能声明什么；规范中的推荐不授予尚未实现的能力。静态声明和自动生成子集不同，不声称任意 A2UI 消息互操作。
- **默认实现**：共享 Panel 组件及样式负责控件、布局、主题、状态和编辑行为；Bundle 只声明绑定、领域标签、分组和已有配置，不注入 JSX、CSS 或事件脚本。
- **证据**：规范成立不等于所有组件已经达标。下文区分默认建议、已确认的场景基线和待补项；验收仍要看实际渲染与操作。

适用的是设计工具本身的界面。用户设计出的 HTML、品牌和视觉风格由其 Design Style/产物契约决定，不能被工具的紫色强调色覆盖。原生参考保留语义与交互，不将旧实现的每个尺寸固化为全局规则。

### 唯一共享基础

共享基础覆盖侧栏与树、内容页框架、基础控件、文字层次、间距、状态反馈，以及
阅读、编辑、新增、删除、展开收起和同源视图切换。所有 Kit 复用相同组件及
`packages/panel/src/visual-components.css` 这一基础样式维护入口，不各自复制
样式、追加覆盖文件或重新拼装常见操作。交互行为由组件实现，不能只靠 CSS 或
文档约定保证一致。主题资源、宿主壳和专业图形资源不构成另一套 Kit 基础样式。

Bundle 作者决定业务信息的归属、关系、次序和合适的已支持形态，组件自动承担
共同的视觉与交互默认值。信息组织是否帮助人理解和改写仍须审视，但作者无需
逐字段选择字号、留白和按钮样式。基础能力有缺口时改进共享组件和原规则，清理
被替代定义；不把同一问题留给每个 Bundle 重新处理。规范和创建技能指向同一
实现，代表性页面核对其效果，不将“一份样式文件”本身视作体验已达标的证明。

迁移 Kit 或升级共享基础时，以主线已确认的完整版本为基准，检查实际加载的
组件、样式与 Bundle 来源。源码、构建产物和测试服务必须对应；旧工作树里存在
同名文件，或只移植几个修复提交，都不能证明已经对齐。新增共享能力按固定提交
交回主线，不能让迁移工作树长期成为另一套基础。沿用同一版本的普通内容修改
不因此新增版本审计或重复安装验证。

## 1. 先确定用户任务，再选择表达

### 共享形态是组件库的组织基础

从“UI 形态 → 信息绑定 → 交互”组合界面：形态负责一致的排版和状态；绑定说明
这些元素代表什么；交互沿已有选择、编辑、验证和保存通道。基础控件、组合形态、
完整工作区是不同抽象层，不因为都出现在 catalog 中就把它们当作同级的视觉原语。
现有工作区继续复用这些形态，不另建一套 A2UI 运行时或扩大生成器权限。

| 共享形态 | 信息表达与现有入口 | 不随 Bundle 改变的默认交互 |
| --- | --- | --- |
| 结构导航 | 记录、章节、真实层级；`PanelWorkspaceTree` 系列，含无层级列表 | 标签换行、选中、独立展开、集合尾部添加；可附加真实状态 |
| 卡片导航 | 标题 + 次要上下文；`PanelWorkspaceNavigation`，目前用于问题轮次 | 两层文字及卡片选中态；不因“没有树”就使用卡片 |
| 字段组与重复集合 | 标签/控件/说明；已有 field/group、`record_map`、related editor | 一组只管理一次间距，添加留在集合末尾，折叠不改变数据 |
| 画布与同源详情 | 关系、流程、导航地图配合 inspector | 同一选择与 canonical 数据，切换不丢未提交编辑 |

新增组件前先判断：是绑定不同、现有形态缺一个通用可选能力，还是确有新的信息
表达方式。前两者复用或增强共享层；最后一种才增加形态，并给出真实用例、适用边界
和状态/交互约定。不能为一个 Bundle 在共享层硬编码名称或复制整套导航、输入样式。

结构导航统一采用 14px / 20px 行高、最小36px行高、8px内边距；长标题自然增高，
不固定高度后让文字溢出。工作区导航标题14px常规字重，分组与选中项500，普通项400。
可选状态/注记独占不压缩的行尾位置，对齐首行；无状态时不占空位，也不虚构状态。
真实层级保留缩进和展开；Function Module、Flow、Research、业务对象、角色等使用
同一结构样式。问题轮次保留“两层卡片”，不强行归并成树。

专业组件可保留领域行为（如流程节点联动画布），但导航条目、分组、展开和新增入口
必须复用已有工作区公共组件，不能在专业分支内重新实现这些基础交互。零子项不显示
空展开箭头。应用配色等选择动作保留 `aria-pressed` 与只读保护，复用公共侧栏及选择
控件，不伪装成记录导航。审查应覆盖含子项、空子项、上下文新增和未归属内容的真实
入口；仅共享一个 CSS 文件或在截图中看似接近，不代表已复用同一基础实现。

这一分工与 [A2UI catalog](https://a2ui.org/concepts/catalogs/) 和
[theming](https://a2ui.org/guides/theming/) 的思路一致：可用组件/绑定是声明契约，
客户端设计系统负责呈现。这里复用本项目已有 DSL，不等同于声称完整协议互操作。

写 DSL 前，用已有提案或普通语言回答五件事，无须新建强制文档：用户要理解或决定什么；核心对象和关系是什么；首屏看什么；选择后如何修改；在哪里看出修改结果。

### 面板自查

语构设计系统（Yugoo Design）的面板本身应帮助人理解、思考、表达，并与 AI 对齐。
新建、修订或迁移面板时，作者与审阅者必须结合目标用户、实际信息量和操作过程回答：

1. **这个面板的信息表达方式，能帮助人理解和思考吗？** 用户能否先把握整体，再理解细节之间的关系；在需要判断的位置，能否看到相关条件、选择、后果、例外与未知，而不必跨页记忆和拼凑？
2. **这个面板的交互方便，符合人的操作习惯吗？** 查看、定位、选择、修改和返回是否连贯，操作结果是否清楚；用户是否需要先学习底层字段、技术标识或特殊操作才能完成业务上的判断？
3. **这个面板的信息量和组织形式，方便人工改写内容、表达诉求和想法吗？** 主次、密度和编辑空间是否合适；相关内容是否能在同一上下文中查看与修改；用户能否直接表达自己的决定，而不只是浏览 AI 的结果，或因普通编辑入口缺失而被迫再次请求 AI？
4. **人的改写能否清楚地反馈到方案，并与 AI 保持对齐？** 用户能否区分 AI 建议、已表达的决定和待确认事项，看出修改结果及其相关影响；保存与后续 Agent 消费的实际边界是否说明清楚，而非暗示尚未实现的同步？

**面板原则上不推荐多个内部 Tab。** 不按底层数据集合、schema section 或字段类别
机械拆页；同一对象或同一次判断需要的信息应就近呈现，优先用对象导航、同源详情和
按需展开组织。Tab 只在确有独立任务或有价值的视图切换时采用，并说明为什么这种
切换有帮助、如何保留所选对象、未提交内容和阅读位置；需放在一起比较的信息不应
被拆到互斥页。此原则不设固定 Tab 数量，也不要求所有面板采用同一种布局。

自查用与改动相关的代表性非空内容，沿一条实际阅读、判断和人工改写路径回答，
在现有任务或交付记录中说明依据、发现的问题和未验证范围，不只写“符合规范”。
迁移还须对照原有主视图、选择与编辑操作；字段齐全不等于体验保留。
需要的表达或交互能力缺失时，应明确缺口，不能把机械堆叠表单当作等价完成。
这是作者与审阅者的工作要求，不新增用户表单、评分、审批或每次全量测试。

#### 独立填写字段的价值

所有显露给用户的独立填写字段，都必须有具体的意义和使用价值。作者需能说明：
谁提供或确认它；它帮助用户作出什么判断，或被后续哪个环节使用；为什么已有字段
不能表达同一事实。仅仅因为 schema 有这个字段，或笼统地说“方便 AI 理解”，
不足以成为独立输入的理由；没有自动化消费者，但确实帮助人比较和决策的信息同样有价值。

- **适用于所有 Kit 的所有 Bundle**：一般性的待确认事项、假设、设计依据、来源说明和补充说明，统一写入所属对象的可选“备注”。不逐记录铺设“待确认与依据”等通用区域，不将备注再拆成数个输入；仅改标题为“备注”而保留原字段组也不算落实。没有补充需求时不强加备注内容。
- 备注中用清楚的文字区分“尚未决定”“暂作假设”和已确认事实；保留未知不等于保留独立的待确认填写字段。直接影响业务设计的规则、适用条件、约束继续使用有实际用途的业务字段。以提问回答、研究证据或校验记录为核心内容的专用 Bundle 保留相应结构，不把这些核心产物误当普通附注，也不以“后续可能有用”为由复制通用字段组。
- 名称、描述等已有清晰编辑入口时不再重复输入。可推导的信息由现有机制展示；技术 ID、版本与溯源元数据通常由系统或 Agent 维护，需要核对时提供可读上下文或来源入口，不要求业务用户重复手填。不具备推导机制时不得假称已自动维护。
- 修订时说明被合并或移出常用编辑区的内容如何保留、后续如何读取与必要时纠正。沿用同一 canonical 事实与保存通道；若改变数据语义，同步 schema、方法、输出契约和必要迁移。不得静默丢弃用户内容、来源引用或精确版本。

在现有面板自查中结合实际阅读与改写验证上述判断，不新增字段打分表或单独审批。

| 需要理解的信息 | 优先表达 | 现有能力入口与限制 |
| --- | --- | --- |
| 独立对象的取舍、分组和摘要 | 分组卡片、列表、按需展开详情 | `record_board`；分组不是新增业务实体 |
| 真实父子结构 | 树、层级脑图 | `record_tree`、`mind_map`；不把普通引用画成包含 |
| 对象之间的关联、约束或依赖 | 有名称的关系图 + 选中对象/边详情 | `relation_graph` 配合 `record_workspace`；显式绑定端点与关系字段 |
| 页面导航及其产物 | 导航地图 + 选中页面/连线详情与预览 | `navigation_workspace`；布局分组不隐含业务关系 |
| 顺序、分支、责任或状态转换 | 流程/泳道、生命周期图 | `diagram_workspace` / BPMN，或受限的 `lifecycle_canvas`；分别核对可读、可编辑边界 |
| 多条记录的同维度比较 | 共享表头的轻量表格或只读矩阵 | 多列 `record_map`、`record_matrix`、`relation_matrix`；不省略条件、例外或引用 |
| 提问、回答及尚未知信息 | 问题卡、选项、补充说明 | `question_workspace`；选项不是答案，跳过不是确认 |
| 调整参数后的直接效果 | 控件 + 同源效果预览 | `preview_workspace` / `record_preview`；预览不等于执行或发布 |
| 理由、来源、报告和整体交付 | 可阅读正文、来源定位、章节导航 | `document_workspace` / `artifact_workspace`；日志不冒充研究结论 |
| 未结构化想法 | 白板、草图、批注 | `canvas_workspace`；手绘线不自动成为 canonical 关系 |

自由输入答案的简答题只提供一个答案输入区，不附加第二个补充输入框；选择题可以提供可选的“补充说明”。已有简答题保存的补充内容保留为只读上下文，使用同一“补充说明”标签，不另称“其他补充”；阅读态去掉“选填”后缀。该规则由共享问题组件提供，Bundle 不重建输入或改写标签。保留的上下文不冒充用户答案，也不在渲染时迁移或删除原值。

普通表单与卡片详情中的多列简单 `record_map.columns` 复用共享表头的编号表格，不再每条重复集合标题。单列保留其所在场景的标题语义；带 `item_fields` 或折叠交互的复杂子表单保留卡片表达。窄容器由表格内部横向滚动，文本域按内容增高并可手动调整；变化只影响呈现，不改变稳定键、添加删除或保存语义。

关联记录表格的详情开关放在该行的操作列，与删除按钮分开。展开后在当前行下方显示通栏详情，收起时不单独占行；保留编辑器状态与键盘可达性。只读模式仍可展开详情，展开和收起不写设计数据。此行为由共享表格组件提供，Bundle 不单独编写开关或叠加样式。

图形应帮助读者发现文本难以直接表达的关系。单个事实、短列表或理由正文可以只用文字和表单；不要为“可视化”而添加无意义节点。缺失能力先明确说明，用已支持的安全阅读方式保留全部事实，不把降级表单宣称为完整专业图形体验。

## 2. 图形与表单必须同源

画布方法的文件归属与内容覆盖遵循 [Bundle 画布创作规范](../.agents/skills/design-bundle-creator/references/canvas-authoring.md)：
每个含画布的 Bundle 用自身 `reference/canvas-guide.md` 作为统一入口，索引
原有专项资料，并从普通方法与还原契约均可达。统一的是生成规范的记录方式，
不是图形类型、领域风格或布局算法。下述共享控件约定只作用于其适用组件，
不能将关系图端口规则强加给 BPMN、Excalidraw 等专用格式。

节点、卡片、连线和详情都绑定同一 canonical 身份。修改名称应更新相同对象的所有视图，不能生成第二份图形专属事实。连线标签说明关系；箭头不自动表示执行顺序，空间相邻不代表依赖，颜色不单独承载关键意义。

需要用户引用编号的分组卡片可用 `board.id_field`，在标题旁用次级文字显示已有只读 ID；展开的内联详情沿用同一卡片标题，覆盖式详情在顶部保留编号。编号不是可编辑名称，不增加编号生成、回填或保存通道。

总览用于定位和比较，详情用于精确编辑。只在需要时展示低频细节，但影响判断的冲突、权限、异常和未知不得隐藏。大图提供已支持的导航、筛选或相关邻域；不能把字号不断缩小来塞进所有节点。只读图明确只读；专业编辑器的文件格式、布局与保存屏障沿原契约处理。

视图选择、展开和滚动属于界面状态；显式保存的画布坐标属于布局数据；对象和关系属于设计事实。不要互相推断。排序仅在契约已有顺序字段和实际操作时提供；引用编号只是定位，不自动生成 order 字段或上下移动按钮。

对象导航只呈现对象及其真实层级，不将关系重复做成导航树。关系在画布中选择，仍由同源详情编辑。单一对象集合不套同名分类根节点；这同样适用于没有画布的树形表单工作区，不按“是否有图”区别处理。直接呈现真实记录，保留其从属记录和上下文新增；多类真实对象保留必要分组。画布入口复用 `PanelWorkspaceCanvasToggle`：侧栏右沿、24×48px、16px 线性箭头，与功能模块一致；切回详情保留选择和未提交输入，不能因简化导航丢掉关系编辑能力。

从属记录尚未指定父对象，或父对象引用失效时，须保留可点击的提示入口，允许查看并修正原记录；不能因无法挂入树而隐藏，也不自动猜测归属或制造占位父对象。多父记录仍有有效归属时在该处访问，其余失效引用由详情提示。

表单与画布互相覆盖时，隐藏但保留挂载的视图不得撑大可见视图的滚动区域。
焦点切换和恢复不滚动外层工作区；窄屏缩放后也须保留画布顶部工具栏与完整入口，
详情长内容在自己的区域滚动，不将整幅画布卷出视口。

保留挂载的受控画布须保留框架测得的节点尺寸与连接点；更新投影不能丢掉测量
状态，使同尺寸的重入等待一次不会发生的重新测量。这些都是暂态呈现状态，不进入
canonical 数据或保存；验收覆盖从详情返回画布及退出后新实例重新打开。

共享 `relation_graph` 节点在上、下、左、右各有一个可双向使用的连接点；
方向由实际起点与终点决定，不由端口所在侧决定。手选端口与自动路由一致，
是当前视图几何，不写成业务字段；重开视图仍按默认右出左入自动布局。
只读模式禁止连线，单父、循环等领域限制仍走原记录创建与保存校验。
自动取景（初始、恢复显示、自动布局、适应画布）最高100%，手动可继续放大；
图的节点与完整标签共同参与布局。画布工具栏与内容区域保持16px两侧留白，
标题与按钮对齐，不能在全幅画布里让标题贴边。

关系图、页面导航图、功能分组思维图复用 `PanelCanvasHandles` 与
`PanelCanvasToolbar` 的连接点/计数呈现，和同一自动取景上限。
标题14px/500、数量12px/400次级色，不混用胶囊计数与裸文字。
数量由 owning 投影明确提供：关系图显示真实对象与合法边；页面地图
显示页面/导航连接，分组 frame 不是页面；功能思维图显示条目/分组，
不把合成根节点当业务对象计数。只有已有可编辑关系契约的画布允许连线；
派生思维图的端口只用于路由，不新增关系写入。页面地图既有布局坐标、
frame 尺寸保存规则保持不变，不因复用控件而改成暂态数据。

连线标签表达关系含义，不重复节点已经展示的“A → B”端点名称。
共享关系图仅对精确匹配两端名称的自动端点串作展示去重，保留关系类型、
端点数量等说明及用户自定义的关系文字；无关系含义时不绘制空标签或占位框。
详情和可访问名称仍提供完整端点，canonical 关系记录不因展示简化而改写。

继承来源使用共享 `RecordInspector` 的轻量关联区，而不是数量徽标或通栏表单按钮：声明的说明与可导航的父类型名称左对齐，父类型可为多个，长名称和窄容器自然换行；详细说明为12px次级正文，关联区与对象详情间距16px。名称旁的方向图标表达“查看来源”，悬停/键盘焦点和可访问名称明确目的；只读时仍可导航。图中摘要与表单详情复用同一呈现，不复制父类型字段，也不把点击查看变成保存或修改继承关系。

单父领域可显式声明 `graph.hierarchy.max_parents: 1`，共享表单提供来源选择，
画布与表单修改同一条边，不另存 parent_ref。祖先的关联记录可由
`record_related_editor.inherit_from_graph: true` 按来源只读展示，自己的记录仍
在原编辑区维护；不要复制父记录、隐藏来源条件或猜测权限覆盖规则。
此场景的左侧树只呈现对象层级，不重复列出已由完整编辑器覆盖的关联集合。
来源选择、清除与子节点创建复用同一保存事务；UI 阻止循环/多父并不替代
Bundle 的保存校验。未声明单父的业务对象多父关系保持原行为。

端点缺失、暂不能绘制的关系必须在画布内提供局部提示和原记录详情入口；两端都缺失也不能丢失入口。只读仍可查看、不可修复，不补造对象或自动清理关系。组件自己的样式高于工作区/记录容器的低权重默认，不能让父级全后代 `button` 或 `label` 规则覆盖嵌套组件的排版。

显式采用有序参与方绑定的关系图保留二方连线与拖线创建；三方以上以原关系的名称、
关系类型及逐角色参与线表达一个联合关系。关系中心只是同一 canonical 关系的投影，
不计为业务对象，不成为新的连线端点；参与线无方向箭头，不能冒充独立的两两关系。
同一对象承担不同角色时保留每一条参与线及角色文字，不按目标对象去重。选中中心或
参与线进入原关系详情；参与方增删/排序和关系属性在共享表单编辑。此可选表达不改变
其他 Bundle 已有二端点、继承或反向操作；真实参与方顺序与画面坐标仍是不同事实。

## 3. 字体、层级与阅读/编辑

条件表单按用户选择呈现适用的问题，而不是把多种语义塞进“位置或条件”等合并标题。
先呈现主选择，再在其后就近呈现适用的二级字段；复用组间16px、组内8px，
不为每个分支另套卡片或重复标题。选择后保持焦点，不自动跳页或提交。
同一数据字段可用共享声明 `label_when` 切换可见标题和可访问名称；不适用项用
`visible_when` 隐藏。两者均不改写用户内容，切回时应恢复已填值。只有明确授权的
数据清理契约才允许清空隐藏字段，不为了 UI 简洁增加三份重复数据或隐式迁移。
例如入口位置随触发方式改称“对话入口位置／操作入口／触发时机”；按钮可不要求
额外输入，后台不显示人工输入方式。“自动带入的信息”与用户输入、通用资料库分开表达。
条件必填必须与实际 schema/validation 的适用条件和阶段对应，不能隐藏仍要求用户
填写的控件，也不能仅凭隐藏就跳过领域校验。若实际约束尚不能表达该分支，先补齐
契约或保留可理解的入口，不用视觉掩盖。验收至少覆盖各分支、切回保留、只读、双语、
键盘焦点，以及保存重开；简单可选说明不必为此新增必填规则。

共用系统/CJK 字体栈；文件名、代码和原始 YAML 才用代码字体。复用 [现有 token](../packages/panel/src/client/ported/token.css)。所有 Kit 共用 `packages/panel` 的基础控件、排版和间距规则；Bundle 只声明内容、组织和交互，不拥有另一套字体、留白或 CSS 补丁。共享规则在原定义处维护，不通过重复选择器、Kit 名称或加载顺序逐层覆盖。宿主负责窗口布局，专业画布负责图形布局；它们不重新定义表单基础样式。下表按信息角色区分样式，不按 Kit 区分。

| 信息角色 | 默认字号/字重 | 使用规则 |
| --- | --- | --- |
| 工作区标题 | 18px / 500 | 一次显示主要标题；不要重复产品名、页面名和 Bundle 名占满首屏 |
| 详情名称、字段分组、关联内容标题 | 14px / 600 | 使用共享标题字重 token 和主文字色，与 400 字重的正文清楚区分；折叠前后保持一致 |
| 重复记录卡片、树节点标题 | 14px / 500 | 保留紧凑浏览层级；功能卡片“功能详情”保留已确认的 400 字重 |
| 主要正文、常规表单值、长文本编辑 | 14px / 400 | 默认阅读和编辑保持字号与文本起点一致，行高约 1.5–1.7 |
| 摘要、辅助说明、密集次级字段 | 12px / 400 | 清楚但次要，不把主要说明、错误或所有字段机械缩为小字 |
| 表格、行内编辑 | 按该内容角色 | 阅读/编辑同列对齐；避免切换导致列宽、行高和阅读位置突然变化 |

卡片摘要可保留**阅读 12px、编辑 14px**的已确认模式：编辑是在更易输入的明确区域进行，而非每次聚焦都放大所有文字。标题不会因进入输入框降为正文；长篇正文不自动缩为摘要。默认规则若与已确认的原生/场景基线不同，应记录适用范围并在对应任务中迁移，不静默改写。

共享 Panel 以实际容器宽度自动选择紧凑密度，不按显示器型号或整个浏览器视口
推断。内容宽度不超过560 CSS px时，常规正文/字段与共享选择控件采用13px、
详情组间12px/组内6px；次要文字保留12px下限，输入框与点击热区不随文字机械
缩小。宽容器仍使用14px与16/8px。阅读产物按自己的实际阅读区域宽度适配，
Markdown标题按正文比例呈现：一级约1.43倍、二级1.29倍、三级1.14倍，
不继承浏览器默认的大标题；段落与列表保持统一节奏。不得用全页zoom、transform、
文字缩放禁用规则或改写用户HTML/iframe实现紧凑模式，保留浏览器放大能力。
此默认针对工具自有阅读/编辑控件，不替代专业画布的视图缩放或用户页面设计。

长文保留完整换行，不能用省略号隐藏关键事实。导航用精简名称，允许换行；详情在内容区显示。中英文混排、长名称和浏览器文本放大都需保持可读与可操作。

详情的顶部可编辑标题是该记录唯一的名称入口：正文不重复渲染同一个
`form.header.title.field`，只读时也只在顶部显示。按当前记录的实际绑定去重，
不按“标题/名称”的文案匹配，不隐藏嵌套记录自己的名称，也不删除 schema 或保存字段。
没有顶部编辑入口或采用常量标题的表单仍保留正文的名称输入。

同一记录组合多个表单投影时，详情容器只承担一次左右留白；仅标题的投影不产生空正文和额外段间距。工作区已有对象导航时，不根据任意关联字段自动增加“返回父级”文字链；真正的继承来源或跨对象追溯保留明确的查看入口。

真实可编辑的记录名称复用共享标题输入与铅笔标记；铅笔只聚焦并选中原输入，
不新增改名弹窗或保存通道。名称后不显示 `*` 来暗示可编辑，原 `aria-required`、
schema 与完成校验仍保留；普通必填字段仍使用原必填提示。只读、派生标题、
身份字段或缺少实际更新回调时不显示可编辑铅笔。
详情标题栏最小高度44px，内部输入与操作控件保持32px并垂直居中；多行只读名称可自然
增高。标题栏作为详情首项时紧接上方提示条或工作区边界，外侧不再叠加顶部留白；
没有标题栏的普通内容保留自身阅读内边距。标题文字与下方分组标题使用同一左起点；聚焦以轮廓和背景反馈，不增加
内边距或占位边框。记录标题到正文的间距由唯一父容器管理，不能再叠加空投影。
标题栏保留共享浅灰背景和下分隔线，以区分对象名称与正文分组；组合详情只调整容器留白，不将标题表面重置为透明。背景延伸到内容容器两侧，标题文字仍与正文左对齐。

字段标题是最小信息单元的唯一可见标题。不要为了“分组”再给它套一层
“实现方式／底座选择”“工作说明／AI 应该怎样完成任务”这样的近义标题。
`form.body.group` 可以不写 `title`，仍保留字段顺序、条件、说明和共享间距。
多字段组只有在组名提供明确的额外语义范围时才使用标题，不把泛化的阶段名
放在每一组输入上；说明文字不能因去标题而删除。

长记录可用声明式 `form.body` 页签按用户任务分开，而不是增加第二份记录或
把每个字段变成页签。共用顶部名称，页内不重复页签标题；默认页呈现用途和体验，
完整指令与资源、行为约定按真实信息归属组织。低频可选资料用共享折叠组，
折叠或切页不清空内容，不作为权限隔离。组内16/8px节奏、键盘页签交互与只读
约束一致；未解决的重要约束须在交接中明确，不能靠折叠伪装已经确认。

内联折叠标题文字与其内容左边界对齐，16px 折叠箭头紧跟标题、间隔8px；
不继承普通按钮的左右内边距，也不在展开时增加正文缩进。长标题自然换行，
箭头不挤压文字；展开后的首个内容组仍遵循16px间距。重复记录标题保留500字重，
功能卡片的“功能详情”保留已确认的400字重。此规则适用于共享字段组、重复记录
和卡片详情，不改变结构树的前置层级箭头或节点缩进。

共享解释器对**单个直属字段、可见标签、与组名精确相同且无 sidecar**的声明
只渲染字段标签，保留必填标记、可访问名及原编辑通道。不同名称的语义范围、
多字段组及有预览的组不靠文字猜测自动删除；近义冗余由作者按上述规范清理。
`label: visually_hidden` 且由组名担当唯一标题的情况保留组名和必填提示，
不一刀切隐藏首字段，也不修改字段名、schema 或用户内容。

## 4. 间距、对齐与空间利用

DSH Web 与桌面版的「Yugoo设计」（英文「Yugoo Design」）入口统一放在宿主顶部工具栏、文件打开动作左侧，
通过公开 utilities slot 排序，不依赖轨迹页签是否存在，不再降到输入框上方。
首次打开设计面板时沿用自动收起宿主导航与70/30初始分栏；用户随后可直接展开
左侧导航，与设计面板共存，重排仅按实际可用空间限制面板宽度。后续设计活动只聚焦
对应页签，不重置人工分栏或重新收导航；切回会话、客户端重挂载也只适配当前布局。
关闭面板只恢复本次打开所收起、且未被后续宿主或用户动作接管的导航状态。
展开后的项目头正常为两行：构思完成度，以及项目名称和克制的打开文件夹图标。
图标调用宿主已验证的原生打开能力，进入当前项目目录；不单列路径，也不把路径
改成悬浮提示。没有原生能力时不提供伪按钮；打开失败就近提示，支持键盘重试。
DSH 侧栏从桌面菜单/标题栏下方开始，两侧信息栏以**下分割线**为对齐基准：
测量公开 `conversation.header` 中实际 header 的顶部与完整 border-box 高度，
相对 overlay 定位原点换算；不能量 display-contents 包装或内部标题行，也不能
只加顶空白而继续固定64px。随宿主页签、缩放、全屏、窗口大小和头部重挂载同步，
菜单栏仍归宿主。DSH 两行头中的图标为24px，其余独立头保留28px；打开失败的
就近提示不撑高这条分割线，也不挤占菜单栏。无可见宿主信息栏时分别推导顶部安全区
与可读的两行回退高度，不声称缺少左栏时仍可严格对齐。长项目名在本行省略但保留
完整名称提示；评分理由和过期状态仍可访问。原有明确启用的单行嵌入模式保留，
不改设计数据、保存屏障或宿主界面。

用现有 4/8/12/16/20/24px 间距梯度：图标和文字 4–8，字段内部 8–12，容器内边距通常 12–16。可编辑详情里的完整内容组默认16px；独立工作区、对话等大容器可采用24px，不将后者套入每一组字段。具体值服从组件与场景基线，不靠增加空白制造层级。

Studio 各页面的顶部标题区采用同一紧凑基线：标题/图标/操作的内容行32px，
上下各8px，正常单行整体48px；标题18px/24px、500字重，图标和普通操作按钮32px。
Kit、Bundle、目录列表与本地副本不再分别设置垂直尺寸。目录的辅助说明在空间充足时
与标题同排；窄屏、长标题、长说明及操作折行可自然增高，不用固定高度裁切内容。
这是 Studio 标题区的已确认场景规则，不覆盖 Panel 内的章节或记录标题。

Studio 的设计套件列表用同一紧凑标题行中的次要外链提供官方套件清单与获取指引，
不增加市场页或把未安装的套件混入已安装目录。外链明确新标签页打开，并保留键盘焦点；
查看清单不安装、升级或修改项目引用。公开文档可访问性与界面渲染分别验收。

- 工作区类组件占满可用内容区域，不再套文档卡片、重复页头或大段说明。明确导航、内容和底栏的空间及滚动所有者，避免多重整页滚动。
- 记录工作区外框不添加正文留白；详情和预览各管理一次16px内边距，单详情、画布切换和多栏详情使用相同规则。不能因组合子组件数量改变，就额外叠加18px或24px外层留白；窄容器调整排列与滚动，不重新制造两层内边距。
- 侧栏按工作区分配的高度收缩，不用内容的最小高度撑大网格行。普通侧栏自身滚动；有侧栏边缘画布入口时，由内部导航独立滚动，保留入口在滚动区外的可见性。长列表的最后一项必须可通过滚轮和键盘到达，右侧详情滚动不带动导航；窄容器仍遵循既有横向导航适配，不用固定像素高度或裁切条目解决溢出。
- 工作区方法提示通过共享 `PanelWorkspace.guidance` 显示在主内容的最顶部、工具栏与记录之前；顶部不再叠加空白 margin，提示条左右贴合主内容区的外边界，不再套一层外侧留白。提示保持完整且高度由文字决定，独立于可滚动详情；侧栏只保留标题与导航。局部字段说明仍跟随所属字段。
- 声明中的可选 `ui.guidance` 是独立操作引导：用一到两句告诉用户打开面板后如何行动，使用现有 locale 资源翻译；不复用 Skill 能力简介、`bundleDescription` 或空状态 `description`。关闭按钮只隐藏当前挂载工作区的引导，编辑和切语言不重新展开，重开工作区可再次显示；不写设计数据或全局用户偏好，不隐藏错误、运行状态、危险操作确认或字段帮助。它不是专业规则或安全约束的唯一载体。
- 操作引导条不沿用表单输入框的内缩边界，不额外预留一列空白模拟滚动条；表单正文继续使用原有12–16px内边距。引导内部文字和关闭控件保留正常内边距，不能把消除外侧空隙误作文字贴边。画布和多栏工作区按主内容区的实际范围展示，不写死宽度或 Bundle 专属补偿。
- 有 owning 侧栏标题的 workspace 用有限 `sidebar_icon` 显式选择语义图标：16px、文字前间距8px、次要文字色、不收缩、aria-hidden。省略保留原中性图标或无图标；不得从标题/Bundle名猜图标，不给记录增加装饰图标，无侧栏表单不强加导航。具体支持以 [DSL](dsl-spec.md#sidebar_icon--authored-sidebar-title-icons) 和 catalog 为准，生成式面板不开放此 authored-only 字段。同级父节点与叶节点保留相同展开列宽，子节点按真实层级缩进，展开操作与选择操作分开。
- 关系图自动布局使用实际节点和全部关系文字尺寸，包括多行标题与端点说明；文字不得被节点或其他文字遮挡。布局和缩放只改变视图，不改写对象、端点、数量或保存顺序。
- 一组字段以共同文字起点对齐；同一工具栏按钮高度、内边距、图标基线一致。状态不要插在操作组中间；返回靠左，主要操作靠右。
- 新轮次采用独立的 `title` 和 `description`：标题是短主题，说明是整轮目的或背景，逐题 `prompt` 仍只属于该问题。左侧固定两层：上层次要“第x轮”（12px常规字重），下层主要标题（14px），随可拖拽侧栏宽度自动换行、不截断；不附带整段说明或状态小字。主内容以轮次标题为标题、下方仅轮次说明。中文标题建议12字以内，英文用短语；这是生成指导，不是截断或长度校验门槛。
- 声明式工作区使用可选 `rounds_source` 绑定独立的已声明 section，记录为 `title`/`description` 字符串，map key 对应保存的数值轮号（不是界面“第x轮”的显示序号）。轮次仍只由真实问题推导，独立介绍不能制造待答轮次或改变固定题、历史只读、回答进度。绑定后缺少介绍时显示通用轮次标签，不从首题编造介绍；查看、切语言和编辑答案不补写元数据。未声明独立介绍的旧显示调用仍保留“标题：说明”/首行标题投影，不改保存原文。
- 单列适合长说明、核心行为和异常处理；只有便于比较的短字段才并列。窄容器按内容区宽度折行/堆叠，不只看整个浏览器宽度。
- 编号在自己的窄列内水平居中，正文左对齐。新增按钮的 **+ 实际图标起点**对齐前一输入框外沿，而不只是按钮盒子。
- 多字段重复记录共用表头；单字段用轻量列表，专业图、来源控件和可折叠复杂表单不强行表格化。需要横向滚动时仅表格 wrapper 滚动。
- 同父对象的权限等可比较记录优先复用共享可编辑表格：同一行保留条件与前置要求，
  自定义条件就近展开，新增/删除仍作用于原记录。继承内容按来源分组只读，不能
  为凑表格复制父记录或省略未知值。单父来源选择可与原详情标题同排，窄容器自然
  换行；不要在表单外另占一整行，也不增加第二份父引用。
- 产物阅读的刷新操作放在当前记录顶部标题工具栏，与可阅读/执行状态并列；不在
  日志和正文之间单独留一行。日志折叠条与正文保持8px边界，刷新不清空仍有效的
  内容，失败与晚响应仍按原精确文件/运行身份处理，不以排版修改弱化日志关联。
- 优先用层级、分组和间距区分模块，不为每个模块添加分割线、嵌套卡片或大圆角边框。

### 详情表单的垂直节奏

先按信息归属划分完整内容组，再决定间距。一个组包括它的标题、输入框或集合，以及集合自己的添加按钮；不能将添加按钮算作下一组，也不能只计算两个标题之间的距离。文字的 `line-height` 控制行内阅读，不承担模块间距。

| 边界 | 共享详情表单默认值 | 间距所有者 |
| --- | --- | --- |
| “功能详情”等展开标题行 → 第一个内容组 | `--ygd-panel-detail-section-gap`，16px | 详情容器的直接内容块 |
| 上一个完整内容组 → 下一个内容组 | 同一个 `--ygd-panel-detail-section-gap`，16px | 内容组的父级布局；跨渲染块也使用同一值 |
| 组内标题 → 输入框或集合 | `--ygd-panel-detail-control-gap`，8px | 该组的标题 header |
| 同一集合的相邻输入行、最后一行 → 添加按钮 | 8px | 集合组件，不再额外增加模块间距 |
| 控件 → 所属字段的辅助说明 | 同一个 `--ygd-panel-detail-control-gap`，8px | 字段说明只持有段前间距，段后为0 |

间距按布局盒子的边界测量，组间从上一组最后一个控件/添加按钮所在的盒子底部算起，而非上一个标题的基线。只由一个层级负责每一道间距，不同时叠加上一块的段后 margin、下一块的段前 margin 和父级 gap。文本换行、输入框增长或添加条目只改变组高，不改变组间距离。

共享详情组件使用语义间距token，而非直接依赖宿主的编号token：实测 Studio 的 `--ds-space-6` 为32px，Panel 根样式则为24px。不能把两个编号体系当成同一个尺度；详情组件在本地定义上述16/8px默认值，避免相同声明在不同宿主里意外变密或变疏，不改写宿主自身的布局token。

因此“使用场景 + 输入框”“核心行为 + 输入集合 + 添加”“异常处理 + 表格 + 添加”“备注 + 输入框”使用相同的组间规则；展开标题到第一组也采用16px。此前先从10px的首组特例统一为24px，最新用户确认将所有组间距收紧为16px，以适应密集详情面板；组内仍为8px。标题字号和常规字重保持已有约定，不增加分割线。本规则从共享 Record Board 内联详情扩展到普通 `record_form`、单 inspector 和声明式 form group；不要求对话、导航或图形工具栏机械使用16px。显式声明的 separator 仍可表达真实分组边界，不能由共享样式默默删除；图与结果预览的 sidecar 保留其意义。

原则来源：[Atlassian Spacing](https://atlassian.design/foundations/spacing) 的相似性、邻近性及视觉节奏，以及 [Carbon Spacing](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview) 的父级 Stack 统一控制间距。16/8px是本产品结合现有token与用户确认的分组方式选定的默认值，不是这些设计系统要求所有产品使用的数值。

## 5. 输入、按钮和编辑状态

输入框、textarea、select 与按钮复用共享控件；常规控件圆角采用已有 `--ds-radius-4`（8px），继承颜色、边框与字体语义。卡片采用对应容器 token，不把所有容器设为相同圆角。已有控件尺寸先复用；同一操作行不能混用不等高按钮。

| 控件场景 | 共享默认 | 保留的例外 |
| --- | --- | --- |
| 常规单行文本和选择框 | 高36px、文字14px、圆角8px、横向内边距12px | checkbox/radio 不套文本框尺寸 |
| 常规长文本 | 文字14px、圆角8px、内边距8/12px、最小高度88px | 保留多行与拉伸；不把所有内容挤为单行 |
| 参数调节 inspector | 紧凑单行高32px、文字14px、圆角8px | 色块与其文字输入同高；标题/说明按各自信息角色定字号 |
| 卡片内紧凑详情 | 按已确认场景正文12px、同一输入边界 | 文本可随内容增长；不将其字号扩散到常规正文 |
| 问题答案组合框 | 外壳持有边界及唯一焦点环 | 内部 textarea 不再叠加第二套紫色边框/outline |

以上约束作用于工具自身的共享控件，不侵入 iframe 内用户设计的页面，也不重置宿主控件。`--ygd-panel-control-focus` 统一取共享品牌语义色；普通灰边框与焦点环分工明确，不在控件自身再堆同色阴影。紧凑工具栏、图标动作和专业画布控件保留任务相关尺寸。

共享单值选择器的触发框与展开菜单使用同一主题：普通字段36px，卡片优先级及筛选
保留28px紧凑尺度；菜单提供边框、圆角、阴影、当前值勾选及键盘高亮。弹出层离开
工作区滚动/裁切容器时继承实际触发控件的语义token和字体，不依赖原容器的祖先选择器，
也不改写宿主页面主题。选择仍使用原编辑通道，空值、失效引用、只读与禁用保持原语义。
这条规则先落实于普通单选字段和卡片优先级/筛选，不表示所有历史原生select已迁移。

Studio 的版本、工作副本及预览 Bundle 选择器通过可选的中性控件渲染口复用同一菜单，
保留32px触发框；未注入该能力的宿主保留原生控件。原生模态对话框中的菜单留在最近的
已打开对话框内，不能靠提高 body 弹出层的层级绕过模态隔离或焦点约束。

GRA 建议收件箱在各宿主复用同一标题与操作行：设置是带图标、边框和焦点反馈的28px紧凑按钮，关闭复用共享关闭控件，不额外占一行或退回浏览器默认按钮。收件箱可以在设计面板未打开时独立存在，也可以弹出到页面根节点；它的公共样式随收件箱入口加载，不能依赖设计面板或对话区域的挂载、祖先选择器及工具类。核查要区分资源未加载、规则未命中、主题未继承和已生效但表达不清，不能仅凭外观把它们都称为“CSS缺失”。

简短、同级的单选项默认采用横向自然换行，声明 `choice_layout: row_wrap`，
复用共享选项行（行间8px、列间20px），左对齐、不平均拉伸、不为普通选项增加
横向滚动。按实际内容区宽度换行，不缩小字号或截断选项。带较长说明、需要逐项
阅读比较的选项采用纵向；已有明确确认的场景例外保留。统一的是选择规则和共享
样式，不把所有单选题、问答卡及历史省略声明一刀切改成横向。
业务对象“什么时候必须填写？”与 AI 能力“触发方式”均遵循横向默认；布局变化
不影响选择值、条件表单、键盘操作和校验。检查双语与窄内容区的完整可读性。

输入必须有持久可识别的标签，placeholder 不替代标签。边界在默认、聚焦、错误、只读和禁用时清楚；聚焦使用一套明确焦点反馈，避免叠加两层同色紫框。错误和链接保留语义色，不能为统一灰色层级而掩盖它们。

编辑保留未修改字段、稳定 ID、引用和用户文本；支持契约已有的取消/撤销。不因隐藏字段、语言切换或查看预览而清空事实。中文输入法确认不触发提交；专门多行输入支持换行，不能把所有 Enter 都当保存。

主要操作强调，次要操作中性，删除使用危险语义。改名在标题旁使用有可访问名称的铅笔入口；普通复制、删除不藏在无必要下拉中。禁用必须说明具体原因，不能以永久灰按钮冒充功能。只读原件与可编辑本地副本分清；删除范围与影响明确，保护原件，沿现有 recoverable 删除能力处理。

Runtime 暴露 `user_continue` 时，宿主复用共享续接栏：有可用对话输入框时放在其上方，无输入框或对话折叠时在宿主区域保留唯一入口。仅在能聚焦实际输入框时显示“调整”，并保留已有草稿；“稍后”只隐藏当前 invocation 的本地呈现，不消费续接权限。只读、未保存编辑、保存或通知未结算时说明禁用原因；点击后的送达状态沿用原生会话回执，不因轮询、切换视图或刷新自动重发。Kit 不添加同义按钮，Studio 试用面板不取得原会话执行入口。

内容组标题已明确对象时，集合条目的添加按钮统一显示“＋ 添加”（英文“＋ Add”），不重复“行为”“输入”“异常”等对象名；完整动作名称保留在悬浮提示和无障碍标签中。没有明确分组上下文的外层新建入口保留对象名，以免混淆操作范围。简化文案不改变集合上限、只读保护、条目 ID 或增删语义。

嵌套信息、业务状态及选中对象的从属清单，都使用集合尾部的同款轻量添加入口，不把添加挤在标题右侧。展开控件复用 `PanelDisclosureIcon` 的16px线性箭头、14px/500标题；状态使用 `aria-expanded` 与键盘按钮语义。卡片只负责直属字段的16/8px节奏，不能用后代 `label` 样式给 radio/checkbox 选项叠加外边距；选项保持24px最小行高、8px组内间距。

简单重复记录卡片的记录标题采用14px/500，直属字段标签采用12px/400次要色，输入正文仍为14px；嵌套复杂表单和紧凑表格保留各自的信息层次，不继承这套卡片标签样式。字段标题使用所选语言的自然表达，不为普通用户重复展示 `Name/Description/Prompt` 等内部概念。

所有备注类字段均应可选，允许缺省或空字符串；真正必须表达的领域信息应以明确的业务字段和契约承载，不能用“备注”暗示可选却在保存时阻断。必填星号与 `aria-required` 来源于面板的 `required` 声明，并不自动生成持久化校验；真实保存和发布校验由 Core 的 schema 与 `validation.yaml` 执行。修改必填语义时必须核对两者，并同步 Bundle 可达的输出契约，不能只删星号。系统集成备注按用户确认改为可选，其他必要信息与安全约束不变。

## 6. 状态、等待、日志与提示

区分载入、空数据、运行中、等待用户、完成、失败和不可用。共享组件提供有限状态及图标；用户只需看到当前状态、结果和必要的下一步，不同时堆满“等待交互”“可以重跑”“不会自动运行”等重复小字。

载入使用共享动画指示，不用静态文字冒充 loading；未知进度不显示虚假百分比。阻塞内容载入时，将指示居中于**对应内容区域**，隐藏不再有效的旧 grid；局部更新保留仍有效的内容与输入。长时任务应显示真实阶段或原因，不能以 spinner 掩盖失败。

内容区域复用 `PanelContentState` 的 loading / empty / unavailable / error 展示，不把读取状态误作执行成功或失败。文档、产物、页面缩略图与预览、流程和白板的缺失内容不再用左上角裸文字；缩略图使用紧凑尺寸，重试保留在 owning 组件。空白源文件须在注入 CSS/图片前判空，不能因 transport 生成了 markup 而显示空 iframe。样式通过现有 owned-styles 生命周期进入 DSH、Companion 和 HMR，不让 Bundle 自带第二套等待样式。

执行状态使用共享 `artifact-status-icon` 的点/活动动画，同时提供名称或可访问文本，不能只看颜色判断。状态是运行投影，不写 canonical。`execution_log` 复用宿主只读桥：绑定 owning Bundle/精确目标，按上限取尾部；在底部才跟随，用户向上阅读时保留位置，切 run/target 清旧行并忽略晚响应。没有精确关联时诚实不可用，不能拿整个主对话冒充该产物日志。细节以 [日志契约](dsl-spec.md#execution_log--embedded-host-logs-authored-panels) 为准。

构思完成度（Clarity）的待评估、评估中、失败、失效和不可用是瞬态工作状态，不是第二份评分权威。状态复用共享图标及12px辅助文字，保留项目标题原有两行布局；详细原因按需展开并支持键盘访问。等待或未成功取得新评估时，保留的分数须标为“上次评估”，不能冒充本次结果；从未评估则保持未评估，不填零分或虚假进度。已保存不等于主对话已开始响应，后台结果已产生也不等于主 Agent 已消费；评估失败不撤销保存成功的提示。

设计建议的小灯泡分别展示待处理建议数量与现有 GRA 调度器的真实活动：等待评审不冒充正在运行，零条建议不表示评审未运行。多项并发时保留仍在运行的反馈，同时说明已失败的项；结束或取消后不残留活动动画，状态同步中断时不将上次运行快照当作当前状态。宽栏提供12px辅助文字，图标栏保留可访问名称与悬停说明；复用共享执行状态图标，运行中的灯泡仅轻微明暗变化，并遵守减少动态效果设置。它不启动评审、不改变建议或评分，不将活动反馈当成耗时优化。

宽侧栏与图标栏均沿用侧栏灯泡；仅当实际入口未挂载、被祖先隐藏或裁切到无法操作时，输入区左侧显示同一灯泡入口。恢复可操作的侧栏后移除输入区入口并保留键盘焦点，二者控制同一建议收件箱、待处理数量与评审状态。新建议的查看动作按实际未读状态出现在卡片现有标题行，窄容器可换行，普通与展开阅读共用；没有未读项不留占位，新到建议不切走当前阅读位置。

建议详情沿原对话列向上展开，按内容高度增长，以历史区域为高度上限；较短建议不
用空白撑满整列，较长建议的条目正文局部滚动，操作与翻页始终可达。展开和收起复用同一
正文层级及卡片留白，移入 Portal 后不因离开对话容器改变字号或被通用消息样式覆盖。
保留每条建议的完整问题、说明和依据，不以删减内容或放大窗口代替阅读层级。

没有对话列的 Companion 内嵌视图以实际灯泡为锚点，在其旁边打开同一个建议收件箱；
浮层按内容和窗口边界限高，不加铺满工作区的白底、遮罩或焦点锁。外点或 Escape
可关闭，内部设置模态框先处理自己的 Escape；新建议自动展开不抢正在编辑的焦点。

输入区灯泡与相邻权限入口沿用同一紧凑尺度：28px高、14px图标、13px文案和8px语义圆角。空间充足时显示“设计建议”，依所在 composer 工具行的实际容器宽度在窄布局隐藏文字，保留图标、数量角标、运行反馈及完整可访问名称；不按整个窗口宽度判断，也不改正常侧栏宽栏或图标栏的尺寸。

普通说明靠近对应字段，复杂演示说明集中呈现，低频帮助按需展开。错误在受影响区域保留，给出可执行的修复/重试，不消失过快，也不把技术路径和字节清单铺在普通用户首屏。

正式 Panel 等待用户修改时，沿用现有保存动作及必要的状态、错误反馈，不在底部重复显示“查看并修改草案，再点击保存”等固定操作说明，也不新增继续按钮。2026-10-17 用户明确取消该冗余提示条，本规则取代此前从 Runtime `must_edit` gate 投影固定引导的呈现要求。版本绑定、正式保存及 gate 消费仍归既有 Runtime 通道，预览和演示不冒充真实交接。

待处理建议的数字角标只保留在灯泡入口，顶部「Yugoo设计」展开按钮不重复显示数量；原有新建议通知语义保留。输入区入口的运行图标与灯泡、文案同排居中，不继承图标侧栏的右下状态角标定位；正常图标侧栏仍保留该定位。

## 7. 保存、预览和真实执行不能混淆

正式 Panel 沿既有编辑屏障、校验、原子保存和继续通道；失败保留输入并明确未保存。图形和表单不能各走一条持久化权威。保存按钮不能把尚未提交的本地编辑说成已发布，Agent 消费已经保存的 diff，不再重复应用用户修改。

持久保存、接续消息排队和 Agent 评估是不同状态。必要的保存结算完成后及时提交普通接续消息；有宿主原生提交回显时复用其真实请求标识，不把消息排队说成 Agent 已开始或已完成。主动评估不能加入保存 RPC 或消息提交前的等待链；评估失败也不能把已经保存的数据说成未保存。性能排查分别记录保存、交接、入队和处理阶段，不用模型推理耗时解释尚未发出消息的等待。

Panel 区域的固定底栏只覆盖 Panel，不能压住宿主导航或整个 Studio；给内容留足底部空间，最后一行和焦点不能被遮挡。常用动作位于右下，次要/撤销在主要动作旁；保存成功的反馈应体现在已保存 UI 状态，不仅弹一句文字。

样例预览不生成 Design Files、不运行 Agent、不改变真实项目；试运行调用真实 Bundle，在隔离项目中生成结果。Studio 里的“撤销编辑 / 演示保存效果”只演示本浏览器保存状态，不发布或回传 Agent。实际保存与演示不可同名冒充。

## 8. 语言、可访问性和主题

宿主/Studio 集中选择语言；Bundle 标题、按钮和提示继承，不在每个试运行增加下拉。Bundle 标签走已有 locales，共享操作文案由 Panel 公共 locales 管理。ID、enum value、路径、引用、原始文件和用户设计文本不翻译。试运行记录其运行语言，切换 UI 不重跑也不悄悄翻译结果。

英文系统文案按角色统一，不以字符串长度或控件标签决定大小写：

| 角色 | 项目约定 | 示例 |
| --- | --- | --- |
| 界面名称、导航、页签、卡片与章节标题 | Title Case；主要词首字母大写，短冠词、连词和介词通常小写（首尾词除外） | Kit Files、Panel Preview、Roles and Access |
| 操作按钮、状态、提示、说明、自然问句式字段标签 | sentence case；句首大写，其余按正常英文书写 | Open workspace、Save panel、Run again、Where does it appear? |

品牌、专有名称和缩写（AI、MCP、API、YAML、JSON）保持正确拼写，用户写的标题和正文不改大小写。这是本项目的产品风格，不是行业唯一规则。同一 locale key 若确实同时承担命名和动作两种角色，先核对消费者再拆分；禁止对所有文案运行大小写转换或用 CSS text-transform 修饰原文。

中文 Kit 统一称“设计套件”，Bundle 称“技能包”；原始文件、技术身份和代码引用保留 Kit/Bundle。设计套件的可选双语展示简介来自 mindset.md frontmatter 的 `display_description: {zh, en}`，原 `description` 及方法正文不变；技能包沿用既有 picker 简介。卡片显示当前界面语言的三行摘要，文件详情窄右栏显示完整简介；缺少翻译时回退原简介，不虚构翻译。标准文件用途由共享文件名/相对路径映射识别，在文件名后显示 12px 次要灰色说明，可自然换行；未知文件不显示用途提示，也不要求作者逐文件维护说明。

所有主要操作支持键盘，可见焦点不被隐藏或底栏遮挡；纯图标操作有名称，选中/展开/只读状态可识别，标题有真实语义层级。普通文字以 WCAG AA 的 4.5:1 对比度为审查目标；大字、非文本控件分别按其准则检查，不把 token 名等同实际对比度合格。

桌面交互目标至少 24×24 CSS px 或满足相应间距/例外要求；触摸的重要目标宜更大。200% 文本放大不能丢失操作；颜色不独自表达关键意义，动画考虑 reduced motion。它们是验收要求，不是当前产品已通过 WCAG 认证的声明。图形所必需的二维画布/表格可以局部滚动，不能让整页被迫横滚。

主题使用共享语义 token 和合理 fallback，不写死黑色主按钮或纯白所有背景；检查实际浅/暗主题。工具品牌强调色不替代成功、失败、警告、只读和链接语义。

以下是保留映射，不推广为所有 Bundle 的强制布局。

| 场景 | 保留的决定 |

| Studio 组件库 | 侧栏底部「面板组件库」；真实同版本目录、可折叠分类树和共享渲染器的固定只读样例；目录、声明、预览分别局部滚动，不提供编辑、状态切换、重置或草稿；缺样例明确说明。可复制完整声明和随包 Skill 指引；不把 DSL 支持等同生成授权，不加载第三方可执行脚本 |

| Studio 预览/试运行 | 预览左 `panel.yaml`、右样例 Panel；顶部唯一试运行入口先检查宿主连接，再按既有流程同轮准备输入并执行；试运行复用左右布局，左测试输入、右真实 Panel，之后修改输入手动再运行；不嵌套模态壳或增加第二行模式按钮、无意义“采用试填数据”按钮、历史入口；首改懒建本地副本，保存不改已安装原件；传输可达不等于执行成功 |

这些决定来自本轮用户反馈及相应共享实现；Function 尺寸已在源码基线 `c8ca697` 的真实浏览器中核对。这里不声称每个场景、宿主、保存或安装包都通过本次验收。

AI 角色画布采用已确认的原型表达：总览卡片将人物头像/角色职责、模型、技能与工具、
产品位置分层；内部视图保留角色外框与角色身份，再表达左侧技能、中心模型和右侧工具。
内部三列的标题在同一行，左右资源容器与模型按水平中心线对齐；技能在一个连接卡片中，
工具/MCP 在另一个连接卡片中，各条真实资源作为内部可选小卡片（名称与短摘要）展示。
容器内长列表局部滚动，不因资源数量增加连线卡片或无限增高整幅图；空侧不补造容器。
内部小卡片选择各自原记录，聚合外壳不是第一个成员或新 canonical 对象；聚合连线保留
所有原引用身份，不将展示聚合写回数据。上下资源带避让，不靠端口偏移掩盖错位。
侧列标题直接使用技能、工具等真实栏目名称，不显示“左手／右手”隐喻标记（最新用户确认）。
右侧是选中对象摘要，不是完整档案。身份之后、长说明之前直接放“展开角色内部／返回总览”
和“记录详情”两个按钮；工具栏和双击是附加入口，不能替代侧栏内的动作。职责短摘要、
模型选择、最多两个产品入口的名称/位置和资源数量即可，不再重复整套资源及交接表单。
资源摘要可列少量实际引用者，更多条目留在总览/原表单中；长内容的完整值不能被删除。
资料库与长期记忆用声明的类型文字及不同语义图标区分。该可选形态不是所有画布的默认：
装饰头像只按稳定记录身份选取，在改名和视图切换后保持一致，不推断人格或用户身份，
不为模型直调补造技能、工具或记忆。触发方式、自动信息、反馈及各条交接条件继续在
同一原记录的完整详情表单中查看/修改，未知位置与缺引用诊断保留。最新用户反馈明确
用精简摘要替代先前侧栏中的可折叠完整事实；这是授权的呈现收口，不裁剪正文或数据。
此只读内部视图隐藏连接触点但保留框架测量，禁止拖拽、连线和删除；查看不产生写入。
这些角色内部视图规则不强加给有真实关系编辑契约的其他画布。
原型迁移验收必须逐项对照视觉层次与交互；仅关系数量或 schema 通过不代表视觉迁移完成。

## 10. 所有人如何使用与维护

1. **仓库贡献者**从 `AGENTS.md` 进入本文；Bundle 作者从现有 `design-bundle-creator` 的 Panel 指南进入。领域方法留在各自 SKILL.md，不把 UI 手册塞进所有 Skill Body。
2. **已安装 Companion 作者**先确认 `design_list_panel_components`，再以 `{ "name": "record_form", "reference": "docs" }` 读取相同包中的组件说明与 `sharedStandards`。新构建的作者材料包含本文；旧包不因 checkout 更新而自动获得规范，缺少该字段时报告版本缺口。
3. **A2UI/DSL 作者**先确定表达意图，再查目标目录、类型和绑定；自动生成只用标为 generated 的能力。共享渲染器继承控件样式不等于自动生成模型已阅读整份规范，目前生成提示并未注入本文全文。
4. **共享组件开发者**在 owning 组件及共享样式落实默认值，按 [组件扩展契约](a2ui-component-catalog-contract.md) 更新能力、文档和代表性用例。不要在 Core/Panel 分支匹配 Bundle 名来补一个页面。
5. **审阅者**检查以下清单。新增决定直接维护对应章节和场景映射；旧规则被替代时保留原因、范围与 owning contract，不另起一份竞争标准。

用现有 Studio 样例逐步形成少量代表性基准：问题、卡片详情、重复记录表格、关系图、流程、报告日志、参数预览。正常、空态、错误、长文和窄容器尽可能复用相同样例，不创建第二套样例权威，也不对每次文档修改全量重测。

## 11. 最小验收清单

- **认知与改写**：回答[面板自查](#面板自查)的四个问题；说明内部 Tab 的必要性，结合实际内容检查阅读与人工改写路径。
- **理解**：能识别主要对象，解释一条重要关系；图形没有编造事实，正文和图形分工清楚。
- **层级**：标题、正文、辅助信息有区分，没有重复标题/大空白/过量小字；阅读与编辑的位置、字号策略明确。
- **操作**：标签、增删改范围、只读/禁用原因清楚；同排按钮对齐，编号及 + 对齐；键盘、焦点和中文输入可用。
- **空间**：真实窄容器、长内容与文本放大可操作；表格局部滚动，固定栏不覆盖内容；图形仍能找到对象和详情。
- **状态**：载入不是静态占位或虚假进度；等待/失败/不可用诚实；日志关联、跟随和切目标不混线。
- **事实**：图和表单同源，未编辑字段/引用保留；样例、演示、真实生成和正式保存没有混淆。
- **语言/主题**：控件与标题继承语言，用户文本不改写；焦点、边框、颜色及关键状态在目标主题中可读。

按改动风险验证并分别报告：结构/绑定、实际渲染与交互、保存重开、Agent 消费、安装包。截图不证明保存，fixture 不证明真实生成，编译不证明好用。纯规范/资料变更只验证引用、材料与入口；不要为此启动全产品回归。

### Studio 组件库的展示容器

- 组件库作为侧栏底部工具，名称为「面板组件库」。目录和预览标题只显示当前语言的显示名；用于声明的机器标识符保留在「声明与用法」，不并排成为第二个标题。
- 小组件按内容高度展示，在中性背景上给出有边界的紧凑样例区；导航提供可滚动的有限容器，完整工作区才使用剩余高度。样例仍使用正式共享渲染器，不复制一份演示实现。
- 目录分类和组件采用一级/二级可折叠树，复用共享 Panel 的树分组和条目；不要为技术标识符增加一层标题。组件库定位为文档：固定只读样例，保留切页、展开、导航等查看交互，不提供内容编辑、状态切换、重置或草稿。预览/声明及声明复制收敛到同一操作行，窄容器可换行，不靠固定高度裁剪。此规则只属于 Studio 样例展示，不改变正式 Panel 的默认容器。
- 版本号是普通 UI 信息，使用 UI 字体和轻量版本标签；包名及代码才用明确含 Windows/Linux 备选的等宽字体，不能依赖浏览器默认 `monospace`。
- 第三方 UI 库是独立的只读说明目录：名称、当前构建实际解析版本与用途。区分基础依赖与可声明的 DSL 组件，不把包名清单变成新的组件注册权威；不暗示所有间接依赖、许可证或升级能力都已覆盖。
- 每个已注册组件应有具体、可阅读的样例；文件、图形和日志使用有限的隔离数据。日志必须标明静态样例，不冒充已连接宿主；样例失败仍显式报告，不以占位画面充当真实渲染。

## 面板自查

新建、调整或迁移面板时，沿一条有代表性的阅读与编辑路径回答：

1. **帮助理解和思考吗？** 用户能看清当前对象、关系、重点和需要判断的问题，而不是只能看见堆叠文字或字段清单。
2. **交互方便、符合习惯吗？** 选择、查看、编辑、增删、排序、展开和保存的入口清楚，切换视图不丢上下文与未保存内容。
3. **便于改写并表达诉求吗？** 信息量、层级、字段粒度和编辑方式让人能够修改具体事实，而不是被迫在多个长说明区反复填写同一件事。
4. **能看出修改的影响吗？** 相关图形与表单来自同一份数据；用户能确认改了哪个对象、保存了什么，以及哪些关联需要继续核对。它不要求新增自动跨 Bundle 改写能力。

默认不把数据存储分区做成多个内部 Tab。只有不同任务或互补视图确实需要切换时才设置，并说明切换目的、保留当前选择和编辑上下文；同一对象的补充说明优先就近阅读、按需展开。

结果记在已有工作记录中，不新增审批阶段或完整产品测试要求。只核对受影响的代表性路径；不以字段齐全或静态截图代替交互判断。

## 独立填写字段的价值

每个独立编辑字段都应能解释：谁提供或确认、它影响哪个具体判断或后续用途，以及为什么现有字段无法表达同一事实。Schema 中有字段、通用“设计依据”标题或为了表单完整，都不足以证明它值得独占一个输入项。

- 普通待确认事项、假设、设计理由和来源解释合并进对象的**可选备注**；其中的不确定性仍需明确，不能通过合并变成确定事实。
- 独立业务规则、约束，以及本身就是问答、研究或证据产物的内容保留各自有意义的控件，不机械地全部压进备注。
- 派生值、技术溯源或已有引用在有用时作为可读上下文呈现，不要求用户重复输入。
- 精简已有面板时保留用户内容、源引用、稳定 ID 和 canonical 语义。语义确需改变时同步方法与输出契约，不在打开或切页时静默迁移；也不只给原字段簇换一个“备注”标题。

普通导航、内容框架、字号、间距和读写控件只有一套共享基础，由共享组件及 `packages/panel/src/visual-components.css` 维护。Bundle 作者声明内容和视图，不为某个 Kit 复制基础 CSS 或重做控件。宿主外壳、主题和专用画布素材各有归属，但不重定义这套普通导航与表单基础。

### 产品设计表单的精简边界

- 一个字段只负责一个决定：整体目标在职责里，每个动作的条件与采用/保存结果在对应行，异常情形与恢复方式成对。不要再用多个大文本框重复同一约束。
- 同一对象需要分页时复用共享文字标签页，选中态用底部直线，不继承按钮圆角；保留键盘切换与未提交编辑。分页不是新的存储或权限边界。
- 技能以能力说明、适用情形、完整正文为核心；可选来源说明获取出处，附带文件列出正文使用的文档、模板或脚本，不代表上传或安装。工具首先说明需要的能力、使用的信息和期望结果，使用限制与接入配置按需展开；未选型时不默认工具类型，也不要求先填接口或 JSON。已有完整接口、配置和来源须保留，精简不得裁剪提示词、Skill 方法或未知 MCP 配置键。
- 多方协作逐对象说明交接时机、任务/资料和返回/失败处理。图形是同份关系的投影，不另维护重复连线表。
- 日常表单可省去重复设计依据/来源面板；人读说明使用备注，但底层 exact pins、来源引用和已有隐藏内容必须保留。任何迁移需明确语义对应，不在打开或切页时自动转换。
