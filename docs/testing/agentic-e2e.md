# Agentic E2E 测试剧本

本剧本用于语构设计系统（Yugoo Design）的开发交付与版本发布验收。测试执行 Agent 扮演用户，经真实宿主对话和产品界面驱动被测 Agent，检查实际执行、设计数据、保存重开与后续消费；不能用手工补产物、脚本模型或一张截图代替业务闭环。

这是唯一维护的剧本。运行结果写入当前任务的证据目录和工作记录，不把逐次日志写回本文，也不另建一套发布计划。入口规范见 [AGENTS.md](../../AGENTS.md)，产品机制以[架构基线](../system-design-baseline.md)、[Bundle 契约](../bundle-contract.md)及所属包源码为准。

## 执行时机和完成口径

- **每次开发交付前：** 必须完成 A 新任务、B 旧项目迁移、C Studio 创作三条主线检查，逐项记录结果。只有编译、单测或页面打开不能完成这项检查。执行过程中修复缺陷后，重跑受影响检查及其下游；同一固定候选未受影响的成功结果可以复用，必须引用原证据并说明依据。
- **发布候选：** 在最终集成版本上汇总三条主线结果，绑定源码和实际构建产物。开发源码、安装候选、已发布 npm 是不同验证边界。其他宿主的扩展矩阵单独记录，不能冒充主宿主通过，也不自动阻塞已明确限定的发布范围。
- **发布后：** 必须完成 P1 从零安装、P2 从上一正式版本升级，再完整复跑 A/B/C 中至少一条。抽样规则见下文，不能以发布前结果替代。
- `PASS` 需要实际观察与证据；`FAIL` 表示行为不符；`BLOCKED` 表示环境或能力缺失无法完成；未执行写 `NOT_RUN`。失败、阻断和未执行均不能计为通过。改变必测范围须明确记录用户或发布负责人的决定，执行者不得自行删项、降级标准或把缺陷改成预期。
- 规范、文档等不改变可执行内容的维护仍需在交付中交代 E2E 状态，可引用对相同运行产物有效的既有结果；没有有效结果就如实写未执行，不能把文档链接检查称为 E2E 通过。

## 开跑前填写一次

可以将下面的指令交给执行 Agent；版本、宿主和隔离目录必须取自本轮已确认的任务上下文，不得猜测或使用真实用户数据：

```text
请读取本仓库 AGENTS.md 和 docs/testing/agentic-e2e.md，执行真实 Agentic E2E。
阶段：<development / release-candidate / post-release>；目标：<固定源码/精确包版本>。
宿主：<已配置的测试宿主>；隔离根：<本轮专用目录>；资源上限：<时限与模型预算>。
先记录实际加载版本和执行计划，再按相应阶段运行全部必需检查。
使用产品对话和 UI 扮演用户，让宿主 Agent 完成后台工作；不要代写产物。
缺少环境或权限时记录具体阻断，不改真实用户配置，不擅自发布或扩大范围。
输出逐检查点结果、证据、未完成项和清理清单，不能只给成功摘要。
```

在现有任务记录中填写这些变量，后续提示词替换尖括号占位符：

| 变量 | 必填内容 |
| --- | --- |
| `RUN_ID` | 唯一运行标识，用于项目名、证据与清理清单 |
| `SOURCE` / `ARTIFACT` | 固定源码提交；构建来源、精确版本和包摘要；注明源码运行、安装候选或实际 npm |
| `HOST` | 宿主、版本、平台、原生模型路由和可用搜索能力；不记录凭据 |
| `KIT` | 实际加载的 Web App Kit 与四个 Bundle 的精确 pin、编译后的执行策略 |
| `ROOTS` | 独立宿主 profile、项目根、系统状态根、Studio 存储、浏览器/Electron 用户目录及端口 |
| `EVIDENCE` | 仓库外的小型任务证据目录，保存结论、必要日志与截图；安装环境、整仓副本和缓存不作为长期证据 |
| `LIMITS` | 本轮总时限、单步等待上限、模型调用预算和磁盘余量；超限保留最小诊断材料并标阻断，不无限重试或新增整套环境 |
| `PREVIOUS_VERSION` / `RELEASE_VERSION` | 发布后检查使用的上一正式版与本次精确 npm 版本，不能只记 `latest` |

使用现有受支持宿主；完整创作主线优先选择具备原生 Agent、搜索、Subagent 和 Studio 的 DSH Web。内部模型网关仅作为该宿主已配置的模型路由，不成为产品或测试者的第二个模型客户端。启动及隔离方法沿用[开发指南](../wiki/development.md#隔离-ui-与宿主验证)。仅设置 `DSH_HOME` 不足以隔离 Core `projectsRoot`、`stateRoot` 或 Electron userData。

**隔离不等于复制整套环境。** 同一测试路径复用当前工作区、依赖 store 和未变化构建，只隔离可写的项目、profile 与状态；只有从零安装、版本对照或确需并行的检查才另外准备依赖。开跑前记录任务目录占用和实际磁盘余量，WSL 同时检查虚拟磁盘所在的 Windows 盘。结束、阻断后不再使用或被新一轮替代的环境，在交接前停止自有进程并清理其可重建安装、缓存副本和中间包；保留结果、关键日志、截图、固定输入标识及必要的最小复现。若确需保留大文件，在同一记录写明当前消费者和解除条件，不因历史引用无限保留整个现场。清理不改变已记录的 PASS/FAIL/BLOCKED 结论；日后重新搭建环境时，仍按本剧本核对输入是否支持复用既有结果。

首次启动隔离环境时确认项目列表为空；继续同轮复测时核对原测试项目身份，不清空既有证据。确认选中的构建确实被宿主加载，记录加载路径与版本；不要改真实用户的 profile、认证或项目。可以复用已校验的只读依赖和完整模型缓存，但必须记录：这不等于验证模型首次下载。模型资源缺失时分别记录结构图谱、语义检索和设计编辑能力，不能宣布整个 KAG 或产品都不可用。

未发布的 DSH 预编译候选按[原始归档安装路线](../../packages/dsh/README.md#unpublished-release-original-archive-route)消费所提供的完整 tarball 清单，保留现有宿主配置。解包后当作工作区项目安装会重新解析包内依赖；这类结果不能冒充原归档的安装验证。区分安装命令、实际加载和原生使用各自的结果，不为测试设置错误放宽构建或权限规则。

首次选中 Kit 后，对照本轮固定来源核验项目 `design_kit` 的完整文件清单和内容摘要，记录实际采用的安装来源或 Studio 当前保存库。相同名称、版本及已验证的构建包不能证明项目使用了本轮定义；已保存库不会随构建自动更新。需要测试新定义时，由原生 Agent 显式采用到测试项目，保留 Design Files、待确认计划和未提交输入，关闭重开后再核内容；需要直接选择安装内容时，可复用不含旧当前库副本的任务专用 Studio 状态目录，保留原库。校准前的结果按其实际来源记录，未变文件的证据仍按本剧本的复用规则处理。

**搜索预检：** 调研前确认搜索和网页读取各自可用。本地 DSH 狗粮测试使用 `@liustack/modsearch`，在隔离宿主 profile 中启用 ModSearch 的 `searchProvider`，保持 `xSearch`、`readPage` 关闭。第三方插件可能独立读取用户目录配置，不能凭 `DSH_HOME` 或 XDG 环境变量认定其配置已隔离；先核对该版本实际使用的配置路径，再通过其支持的隔离配置或测试进程环境提供已授权的搜索凭据，也可在授权范围内只读复用已有配置。不要用测试用的 `config set` 等操作改写真实用户配置。选择具有有效凭据的搜索引擎，确认宿主的 `web_search` 实际选择 ModSearch 提供方；网页读取继续使用宿主已配置的读取工具。安装候选测试只补搜索配置，不能因此把已安装产品包替换成源码链接。模型网关配置不能代替搜索凭据，默认 DeepSeek 搜索提供方的失败也不能当作 ModSearch 的测试结果。

使用本轮指定的狗粮网关时，核实际宿主模型路由，不另建模型客户端。记录搜索插件精确版本、实际解析路径、选中的搜索/读取提供方和凭据是否可用，不记录密钥值。通过真实宿主对话搜索一个公开主题，再读取其中一条来源，保留原生调用与结果。`web_search` 成功不代表 `web_fetch` 或 `read_page` 可用；有多个提供方时明确配置选择，不能只凭插件已加载或 key 已配置宣布通过。复用配置只覆盖本轮隔离环境，不改正式 profile。预检通过不能代替 A-RESEARCH 的计划交接、来源约束和报告验收。外部网页搜索失败与 KAG 语义查询的执行结果分别记录。

**角色边界：** 测试 Agent 可以在 UI 输入需求、回答问题、修改和保存 Panel、读取日志/文件核证。被测宿主 Agent 必须通过其已安装技能、原生工具及受限工作副本完成生成和修订。测试 Agent 不替它写 canonical JSON、BPMN、评估、审查结果或 Studio 候选，不替它调用 Chrome 来完成后台创作。人工编辑只在剧本明确的用户步骤发生，并记录由谁修改。

**先核输入，再发送。** 浏览器自动化的键盘输入、粘贴和表单填写可能有不同的回车语义。先确认目标编辑器及已有命令选项：选中 `/yugoo` 后只填参数，不能再叠加完整命令。普通对话先完整输入并核对编辑器中的文本，再点击发送；会把换行当作发送的键盘工具应使用保持原意的单段提示，或已验证的多行输入方式。发送后核对实际用户消息，不能只凭工具调用参数认定输入正确。误发时保留实际消息和执行结果，停止误触发的运行、清理测试者自己的残余队列，先查清已发生的变更再继续；不能把输入错误记为产品门禁，也不能回退环境或改写回执来伪造原计划已执行。

若某步失败，不用后台 API 绕过失败的 UI 入口再计通过。可以只读诊断，保留失败后修复并重新验证原路径。运行状态轮询采用有界等待；`accepted`、`queued`、`in_progress`、`due` 都不等于完成。

涉及 token 或耗时验证时，分别记录普通响应、上下文压缩等辅助模型调用及缓存读写用量，按会话及模型调用/结算身份去重，避免同一调用的多个用量事件重复累计，并保留不同实际尝试各自的用量。宿主的普通响应计数可能不包含辅助调用；失败摘要没有用量记录时标为未知，不能计零，已有汇总只能称为已记录下限。区分文本字符数、模型 token 和实际账单，不把缓存读取或提示词体积缩减直接换算成费用降幅。记录实际上下文容量、最大输出及压缩预留配置；只在隔离环境调整测试参数，并保留变更前后值及原因，不能据此声称同条件优化。耗时区分模型、工具、压缩、人工等待和机器资源异常，不能把受内存或磁盘压力影响的结果单因归责于模型。

核查模型实际输入时，区分原始工具结果与上下文裁剪后的结果。同一 `toolCallId` 可能有多个结果版本；按下一次请求前的 `compaction/prune`、`shadowedSeqs` 和替代消息核对有效视图，不能用首次完整结果证明模型看到了正文，也不能用最后的裁剪片段证明远端抓取失败。保留相关序号、长度和必要段落定位；完整请求载荷不可得时明确该边界。重用已取得原文的定向阅读属于修复复验，不覆盖原失败或冒充首次成功。

浏览器网络诊断只回显白名单元数据或经过筛选的必要正文。字段或段落提取失败时记录未取得，不回退打印完整记录或响应尾部；Cookie、Authorization、Set-Cookie 和带 token 的连接 URL 不进入模型可见的诊断输出与证据。解析器检查使用合成输入，不复用真实认证数据。

## UIUX 实际操作闭环

用户界面变更必须执行这一节；范围是受影响路径及其相邻共享状态，不新增用户审批或重复完整产品审计。

1. **先审交互成本。** 用一句话明确用户目标，从正常页面入口梳理最短可用路径：用户需要理解什么、作哪些决定、在哪里操作、怎样知道完成或失败。检查是否暴露内部实现术语、引入不必要的页面或确认，以及新流程是否丢失已确认的交互。复用 [Panel UIUX 标准](../panel-uiux-standard.md)，不得以外部技能建议覆盖现有共享样式和用户确认的场景基线。
2. **技能辅助审查。** 可用 [ux-heuristics](https://github.com/wondelai/skills/tree/main/plugins/ux-design/skills/ux-heuristics) 检查可发现性、操作成本、反馈与错误恢复，用 [web-design-guidelines](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines) 检查控件语义、键盘焦点、表单状态、主题和布局。按所用技能读取其规则；技能不可用时仍执行本节检查，不因缺少技能跳过验收。记录具体问题及影响，不以分数代替实际通过。
3. **真实点击并看屏幕。** 在 9222 Chrome（不可用时记录实际使用的浏览器）确认加载当前实现，从可见入口完成操作。操作前检查真实窗口未最小化且目标页面 `document.visibilityState === 'visible'`；若页面隐藏导致轮询暂停，先检查并恢复窗口环境，不用伪造的 visibility 事件或修改业务状态冒充实际操作。检查入口、按钮位置和文案、操作次数、成功/失败反馈；覆盖适用的取消、重试、键盘及未保存输入保留。实际查看渲染截图或屏幕，检查未样式化控件、层级、间距、对齐、溢出、可读性及相关明暗主题。DOM/计算样式用于定位原因，不能替代看屏幕；不从隐藏 URL 或 API 绕过入口缺陷。
   发送、保存等变更先核工具结果和真实界面或原生接收回执，再等待后台；输入已填好或点击已发出不代表提交成功。截图须对应已核身份的目标标签页，必要时先正常激活；背景截图拍到其他前台页面时标为无效，不能据它接受或拒绝产品。恢复前景或切换报告后，须等待异步正文实际就绪（例如读取区不再 busy 且正文出现）；固定短延时后的 Refreshing 截图属于过早采样，不能据此判定产物不可读或终态同步失败。
   界面偏好从公共工作区右上角的两个图标按钮直接操作：中英文互换、浅深外观互换，不弹出菜单；当前跟随系统时从实际外观切换到相反外观，宿主原有跟随设置保留。该处不再有关闭×，DSH原工具栏按钮仍能收起和重开。核普通面板、关系视图与空态入口，窄窗/键盘/失败恢复，以及切换后的当前记录、滚动和未保存输入；设计正文及文件不能被界面语言改写。DSH沿公开Host设置、Companion沿现有本机设置，分别检查实际生效与重开恢复，不用localStorage探针代替Host保存；关系画布独立外观须可恢复跟随页面且不重排。
   字段说明抽查其实际用途与交互：自明标签无冗余帮助，必需要求直接可见，格式/边界/选择后果的补充说明经同一帮助组件悬停、聚焦、点击及Esc关闭；同一说明不重复。条件输入显示时才有相应标记，未完成草稿仍能按原入口保存；在窄窗核常显说明换行、帮助不遮挡控件且可读到末尾。
   页面地图变更还应通过画布工具栏添加操作旁的双按钮在地图与公共规范间来回切换，再用右侧边缘控件进入具体页面详情；确认没有额外的切换行或重复标题栏，两种操作各自明确、地图视口与未提交内容保留，同级章节在展开和收起时沿用同一容器。
   页面计划尚无 HTML 时，正常详情仍可阅读、修改名称/用途并全局保存、重开；已有原型的预览与详情须保持同一记录，仅查看详情不重建原型文档或丢失其输入。实时 Worker 落盘时当前内容仍可读。在当前原型留下未提交表单、滚动位置及本地成功态，通过另一 Bundle 的正常创作保存触发一次无关更新，核当前 iframe 与输入保留；再核显式刷新、当前 HTML/关联样式更新，以及切项目或读取源后旧内容和晚消息仍隔离。涉及“调整”入口时，先在宿主输入框留下未发送草稿与光标，再点击调整；核焦点回到真实宿主输入框，草稿不改、不自动提交。
   涉及共享样式或页面／场景全预览时，在窄容器实际切换适宽与原尺寸（100%），以原尺寸阅读正文并横向滚到最右端、纵向读到末端，再回到适宽；中英文入口均可发现，既有动作顺序、当前页面、入边选择上下文、表单输入和颜色草稿保留，只读时仍可选择阅读尺寸，切换不重建文档或写入设计文件。
   交互原型含表单时，实际检查空值、有效值、键盘提交及取消，本地校验和提交事件应工作。涉及预览沙箱变更时，另核原生表单和绕过提交事件的 `form.submit()` 均无法向外部 action 发请求；不能以几何检查代替交互或网络边界验收。
   流程节点详情检查图选中与左侧定位到同一节点、连续滚动到末项、图与详情切换保留草稿及画布位置；节点名称、角色、分支仍来自 BPMN。旧流程内容补齐时，先明确只更新该 Bundle 的项目定义，再由真实 Agent 按当前方法迁移其内容。核对其他 Bundle 和已有人工修改未变；提示可重试且不阻断普通阅读/保存，不能用全 Kit 替换冒充单 Bundle 兼容。
   页面、流程节点排队/生成时核滚动日志和内容状态作为同一组居中，已有产物保持可读；完成、失败、取消后整个运行区撤掉，原有重试仍可用，新 run 不混入旧行。终态后再等一次轮询并切回，不能由晚响应恢复旧控件。调研方向先检查计划编辑，再检查有结果后的问题与真实日志只读、最终结论无 Details；同一方向的日志须在 Worker 运行中及结束释放后均可查看，长日志能滚动到末项，切换方向不会混入另一个执行或父会话历史。已释放 Worker 通过当前 Host 的公开只读持久化接口读取，不恢复 Agent 或取得写所有权；日志不可用须有诚实反馈，不推测逐题检索关联。权限表检查允许/禁止、长条件、单元格原地编辑及继承来源只读。GRA 检查三档停位、说明切换后弹窗尺寸稳定、原保存值与独立运行频率，以及取消不保存、保存不触发审查；界面通过不代表已验证严格文件读取边界。流程详情核其当前流程主标题与公共分隔线只出现一次，流程信息与流程节点集合分别使用一级灰块，集合内节点保持白卡、不重复同名流程外框；首次打开或返回概览保留分区标题可见，从侧栏选另一流程只显示该流程，选节点在当前流程页内定位，草稿不丢。具名子记录的名称在共享标题原地编辑，正文不重复同一输入；添加操作保持普通字重。
4. **修复后重走。** 对发现的明显 UI/UX 缺陷，在所属共享组件、样式或流程中修复，再从同一可见入口重走受影响路径。新增/修正控件应检查代表性的共享使用场景；复用无变化的证据，不无限扩大测试。
   灰色内容块的标题须对照普通文字、可编辑名称和带操作/帮助的组合，核开闭后的实际标题行高度、上下内边距与正文起点；共用类名不能代替最终层叠和布局检查，内部标签不得重复叠加标题留白。
   涉及新增记录时，分别从连续卡片和普通详情的实际 Add 入口检查：新记录进入草稿后名称得到焦点；延迟返回前的切换、取消及只读转换不被晚结果抢回。两种组件拥有不同的创建路径时，不能用其中一种的焦点测试代替另一种。 已有的新增意图弹窗另核首个可编辑控件的焦点与取消，不把请求尚未发送当作记录已经新增。
5. **分开记录结果。** 在同一任务记录里写明功能结果、UIUX 结果、实际操作路径、视觉/交互发现、修复与复查证据、未测试边界。适用的 UIUX 检查未通过时，功能成功也不能把该检查点记为整体 `PASS`。浏览器阻断时写明未完成实际操作，不用编译、API 成功或静态审查填补。

只读工作区仍须能展开、选择记录、复制和查看来源，操作前后设计内容不变；不能用整区不可交互代替字段与保存的写入保护。保存续作的可选宿主问题快照不可用时，验证已保存回执仍只投递一次普通续作；另核真实保存、项目切换和送达失败仍可见且不自动重发。故障注入的客户端探针与实际 Native 消费分别记录。

**完成前的最低检查：** 实现者负责从正常入口完成下面适用项，不把基础可用性留给用户找问题。涉及 Studio 反馈时按[统一反馈映射](../panel-uiux-standard.md#studio-信息反馈)核对；没有发生或无法触发的状态写明未测，不用成功截图代表失败恢复。

| 检查 | 不通过的典型情况 |
| --- | --- |
| 入口与已有布局 | 只能靠隐藏 URL 或解释找到入口；已确认的搜索、导航、操作菜单在合并后消失或换位 |
| 控件与反馈外观 | 原生默认按钮/单选/复选、裸报错段落、错误主题色、遮挡或溢出；仅检查类名存在；漏看选中导航内部留白、独立展开列和专业画布外层标题的实际层叠；同级内容卡片各自定义表面、章节与记录糊为同色平面、普通字段普遍加粗。涉及共享卡片时比较智能提问、功能模块和嵌套记录的真实组合；同级页面标题在无说明/有说明、普通表单/流程/报告/画布、阅读/编辑/预览切换及宽窄容器下对照真实高度、底色、分割线与操作尺寸，说明不得重复叠加间距。业务编号在普通表单、问答、调研计划/报告和页面预览切换时仍对应同一记录；固定设置与普通分组不露技术键。构思完成度标题带冒号、常驻 U/S/T 与原进度条同时可读，悬停或键盘聚焦显示完整维度名称及解释。建议卡不重复状态标题行，接受/拒绝/稍后保持32px，详情展开保留日期与翻页 |
| 父级范围与组内卡片 | 对照功能模块和验收标准；点击分组名称只显示该组，侧栏箭头只展开子项，正文主标题保留公共下分隔线，不重复包装为同名折叠框。每个功能点、验收条目是正文一级灰块，块内正文沿用基础表面；不能因把分组提升为当前页而丢掉灰色分割层级。子项快捷定位须揭开其内容块并看见标题；组内手动滚动/到达末尾、过滤、改组、删除末项、图选记录和调整宽度后，当前范围及子项选中仍对应实际内容。编号只显示明确的业务编号，隐藏数据键不抬升，分组不虚构编号。卡片直接编辑同一面板草稿，核对切换保留、全局取消及保存重开；保存成功、失败重试与全局取消保留当前详情视图、分组、选中、折叠和滚动，真实生成结束仍按原规则展示脑图；标题右侧上移/下移/删除常驻，取消删除保留条目，已有拒绝记录可读且可恢复。多行框一行内容不留大块空白，长内容自动最多五行后内部滚动，手动拉高后继续输入和折叠重开保留高度。导航和查看不得修改设计数据或滚动宿主对话 |
| 真实状态 | 同时显示运行中和已完成；下载发起被称为已保存；校验未通过却声称可用；保存忙碌冒充 Bundle 执行结束，自动切到脑图；正常生成缺产物时同时堆叠缺失警告与执行进度，或真实读取/解析失败被等待动画掩盖。对照流程、调研报告和页面预览检查排队/运行、缺日志通道、错误重试、已有内容与结束/失败状态 |
| 错误恢复 | 错误只有内部术语；无重试/修复入口；要求先丢弃修改才能继续；取消后仍被旧结果覆盖 |
| 输入与操作成本 | 切换视图丢输入、同一动作重复确认、多处保存含义不同、增加无必要的页面或决定 |

**复发缺陷必须回到共同原因。** 在当前工作记录写下：受影响路径、具体根因、原检查为什么漏过、共享修复位置、回归覆盖以及原路径复查结果。先判断是资源没有加载、选择器/主题不生效、绕过共享组件、状态契约错误，还是已有实现在集成中被覆盖；不能仅以“加一个 class”结案。可机械验证的问题加入最小有效回归，并证明能识别原缺陷；操作成本、视觉层级等仍靠实际浏览器审查。复查一个受影响的共享使用场景，复用其余未改变的证据。维护现有规范和本剧本，合并或替换重复/过时条目，不为每个问题另建清单或审批流程。

样式检查同时覆盖交互控件与错误/状态反馈。涉及插件样式加载或发布投影时，核对实际样式标签的 `data-plugin` 与 Host 加载的包 ID（含作用域），并验证旧版本到新版本的替换与清理；仅核已安装文件或人工设置主题变量不能证明页面正在使用新规则。`packages/studio-ui/tests/control-style-coverage.mjs` 检查渲染节点是否命中有效的作者样式，仅用于发现明确漏口；不能证明浏览器中的最终层叠、主题、布局或交互合理性。开发交付记录应包含固定源码/实际运行构建、可见操作路径、功能结果、UIUX 结果及剩余缺陷，并链接已有证据，无须新增报告模板。

例如 C-ARCHIVE 必须从列表上的“导入”走到选择文件、错误/成功反馈和刷新重开，并查看 `…` 菜单的导出/删除控件；后端接受归档不证明入口可找到、控件有样式或用户能恢复失败。相同原则适用于 Panel 保存、Studio 编辑与 KAG 操作。

## 运行模式与 handoff 覆盖表

先读取所测 Kit 实际策略，再核下表；策略发生合法变更时维护剧本，不能为了测试修改 manifest。这里覆盖的是机制，不是把这些 Bundle 固化为所有设计任务的必经阶段。

| 检查 ID | 默认入口 | 必须观察的运行/交接 |
| --- | --- | --- |
| A-QA | `smart_questions` | `main` + `must_edit`；有效用户编辑保存前不得结清交接，保存后原会话读取真实回答 |
| A-RESEARCH | `research` | `main` + `user_continue`；先发布当前计划并等待明确继续，普通聊天不自动执行计划 |
| A-FUNCTION | `function_modules` | 默认 `subagent` + `none`；真实独立 Producer 完成校验和发布，无凭空增加的用户编辑门槛 |
| 提案阅读/修订 | `business_data`、`business_rules`、`role_access`、`ai_agent_capabilities` | 以实际 manifest 的 `none` 为准，提案发布后可继续编辑、保存和重开；不得要求随意修改字段才能继续。未决选择保持未决，发布不等于用户已确认 |
| A-FLOW | `flow_design` | 默认 `subagent` + `none`；Producer 整合两个独立 BPMN，覆盖实际精确路径 Worker 委派和返回 |
| A/B-GRA | G、R、A | 原生后台评审、结果发布和前台建议处置；评审不取得设计写权限 |

省略 `execution.mode` 的默认值是 `subagent`。Producer 执行与文件 Worker 委派是两个维度：Flow 输出了两张图并不能证明 Worker 跑过。Flow 方法允许串行执行，但本剧本需要覆盖委派机制；串行成功可以单独记录，Worker 覆盖项仍未通过。宿主不支持某模式时报告能力缺口，不静默改为主 Agent 运行来补齐表格。前台 Bundle 与后台 GRA 也不是同一种 Subagent 测试。

## A：从新任务走完设计协作

### A0 新建与推荐

通过宿主正常入口发送：

```text
使用 Yugoo Design 新建 e2e-<RUN_ID>-new 项目，选择 Web App Kit。
我们是六人设计工作室，希望做一个客户反馈处理工具。客户提交修改要求，
设计师判断是否在原定范围内，需要时由项目负责人确认范围和交期。
现在不写实现代码。请先指出最重要的未知项，推荐合适的下一步及原因，
等我选择；不要替我确定业务规则，也不要一次执行所有设计。
```

检查项目身份、根目录、Kit pin 和空初始状态。推荐应针对此请求、引用当前可用能力并说明原因；不要求固定措辞或固定排序，也不能虚构不存在的 Agent/Bundle。保存推荐与用户选择记录。随后明确选择先问答，不能用测试提示中已经列全流程来冒充 Agent 的推荐。

### A-QA 用户编辑交接

```text
先运行智能提问，聚焦谁能确认新增范围以及退回补充怎样处理。
请展示问题面板，让我填写后再继续。
```

1. 核真实 `main` 执行、问题产物与 `must_edit` 待编辑状态。新应用的“应用基础”按身份需求、内容保留、使用设备分别记录；用户尚未表达的答案保持未知，不从团队场景预选登录、数据库或部署方案。先不保存，只在聊天说“继续”；它不能假定问题已回答或把未编辑状态结清。
   题干保留必要问题、上下文与后果，完整选项只在选项区出现一次。核实际生成的数据和可见卡片，不把模型写入题干的重复选项误判为重复渲染。
2. 在真实问题 Panel 填写适用回答：设计师可处理原范围内且不影响交期的小改；新增页面或交期影响由负责人确认；退回时保留反馈，由设计师补充再提交。本案例由测试用户明确选择需要识别使用者、保留内容；登录方式、共享、跨设备和使用设备只按实际表达填写，不从这些选择推导技术栈。旧项目保留原登录/存储题及其 ID、值和补充内容，不自动换题或清空。不要为凑字段伪造其他需求。
3. 保存后记录改动、项目 checkpoint 与交接结果。要求宿主复述已保存的决定，核它实际读取到了回答，而非只回显聊天提示。

若本轮涉及 Git 历史恢复，使用隔离的恢复样本检查旧 Journal pin 缺失的路径：分别覆盖原 Agent 发布已缺失，以及原 Agent 发布仍在但最早 Panel 释放版本已缺失。实际连续编辑、保存两次并重新打开，核当前内容持久化、旧 Journal 保留、没有伪造旧 `must_edit` 消费或把后次保存当作缺失的最早释放。缺失历史不应导致后续保存出现 `save scope has ended`。同时保留有效交接只结清一次、取消不写入和并发发布冲突不覆盖胜出内容的断言；自动回归与实际宿主结果分别记录。

通过标准：查看和编辑指引使用当前项目 Panel 的真实宿主入口或返回链接，不把用于 Kit/Bundle 创作的 Studio 链接改称为产物入口。若该轮调用 Studio 目录或创作工具，核工具实际返回的创作用途和项目 Panel 入口说明，再实际打开 Agent 指向的页面；system 指引存在或工具返回了合法 Studio URL 都不能替代这个导航检查。用户编辑确实保留；交接只结清一次；被测 Agent 使用保存后的事实；不会自动自答、制造确认或覆盖用户输入。

### A-RESEARCH 计划确认与实际调研

```text
请研究现有工具怎样处理“收集反馈”和“承诺执行”的区别，
以及退回补充后重新提交的交互。范围限制为两个方向、少量一手来源。
先给可调整的调研计划，等我确认再检索。
```

1. 核 `user_continue` 暂停与当前计划版本。可在计划中把一个方向改为“退回原因如何保留”；保存计划不能被当成开始调研。
   实看宿主继续条：开始、稍后及可用时的调整；调整只聚焦原输入，未发送草稿与光标保留。检查控制台没有 slot 崩溃；缺少可选输入能力时仅隐藏调整，不影响开始、稍后和面板。
2. 发送一句普通修改意见，确认它更新/讨论计划而没有误触发执行。
3. 通过真实“开始调研”动作或该版本声明的继续别名确认。观察宿主原生搜索调用、来源、方向进展、报告文件、综合结论及终态。
   调研或修订长文本时，可用宿主已有的按行或范围读取定位相关原文；直接读取与定向读取使用当前设计文件，具体选项沿宿主工具说明。
   发生无可用证据的方向时，核 Worker 没有为满足文件要求写空壳或诊断报告，前沿返回该项失败且没有成功产物收据，Worker 的可见失败原因传给执行器，独立成功方向仍保留；执行器沿既有失败接管和部分结论路径继续，缺少证据的 `findings_file` 保持空。保留失败尝试与日志，不把正常结束的原生 turn 或物理文件存在当成业务证据成立。
   专项验证须观察真实 `design_delegate` / `design_delegate_frontier` 及其原生 Worker；串行执行的来源失败不能代证 Worker 分支。已有本次成功收据的候选若证据拒收，只做有依据的范围内修正并复验；仍不合格则如实未完成或失败，后续沿普通 Owner 修复或已获授权的恢复继续，不把置空引用、强纳无依据报告或改写收据当作完成。此边界与未写入的失败方向可形成部分结论分开记录，保留成功产物精确集成的负例。复核已有方向而本次无结果时，原报告字节与原引用保持不变，不能因旧文件存在生成本次成功收据。成功收据要求该 attempt 经现有 write、edit 或脚本产出路径成功写入；允许经验证后显式写回相同字节，写入被拒绝、编辑未匹配或只运行诊断脚本不算新产出。

涉及继续守卫时，记录计划暂停与确认动作各自的原生 Host turn。新的用户轮次必须进入现有计划、动作和版本校验，不能残留上一轮的等待标记；同轮的重复调用（包括停止回调后继续排入的消息）仍应拒绝。main 执行的延迟结算属于原调用轮次，不能覆盖新轮次的等待状态。

若本轮给出来源数量或类型上限，核对实际报告全体引用的文档 URL、来源列表和 `source_urls`，不能仅数域名或书目。抽查重要结论对应的原始正文与适用范围；页面未提及不等于产品不支持。概述、表格和综合结论应保留同样的证据限定。分别记录 Worker 自查与 Producer 的原文核验，结构校验通过不能代替事实验收。

涉及版本化来源校验时，区分普通草稿保存与完成交付：草稿不依赖历史读取；完成时需读取引用的精确提交、文件及可选 JSON Pointer。提交存在或当前文件存在不能替代该历史目标。用一条已核实的错误定位检查完成诊断，再从真实 Agent 入口依据历史内容修正；不自动改 pin、删除原引用或阻止项目打开。保留当前已删除但历史存在的有效来源。

通过标准：执行的是最新确认计划；有实际搜索/读取来源证据，报告引用能对应来源；结果文件可打开，刷新后仍在；参考机制没有被擅自写成已确认需求。搜索不可用记阻断，不允许测试 Agent 补写报告或以模型记忆冒充检索。

调研活动历史变更时，保留同一真实方向的搜索与读取记录，在后续无需重新检索的修订及正常 Host 重启后打开 Details，核仍能读取原已观测记录；当前执行优先，历史不重新成为活动滚动日志。失败方向保留指定来源及空结果，侧边状态与 Details 应表达真实失败，仍可切回计划编辑且不丢草稿；不能为了显示历史生成报告或重跑检索。分别核对真实 Host 来源、精确委派与父子会话关联、错误项目/会话拒绝和原生记录不可读时的恢复提示。普通 Workspace 轮询不得反复扫描主会话历史。

### A-FUNCTION 独立 Producer 与无交接完成

```text
根据已保存的回答和调研，梳理客户反馈处理所需的功能模块。
本轮只覆盖反馈提交、范围判断、负责人确认、退回补充和状态查看。
请保留已经确认的边界，不加入自动批准或自动承诺交期。
```

核原生 Producer 身份/父子关系、实际工具调用、校验、发布和终态。主 Agent 不能自行写文件伪装独立 Producer；`handoff: none` 不应产生额外的必填问题门槛。

局部或跨 Bundle 修订时，对照当前真人请求、主 Agent 的任务拆分、实际 Producer 输入和最终文件。DSH 的新执行输入应分别保留本轮真人输入与 caller task plan，包含同轮补充及多段文本。沿真实原生问题卡路径分别检查选项和自由输入：问题上下文、所选标签、自由输入原文须交付给 Producer，后来的回答或纠正不能被较早的聊天请求覆盖。问题是 Agent 撰写的上下文，不应当作真人陈述；自动通知、压缩摘要、普通工具结果和旧轮次不能冒充当前真人要求。核任务拆分没有缩减业务目标、替换角色或丢失同一 Bundle 的其他修订，并保留当前 Bundle 写入边界。原生问题卡的“继续”选项不自动冒充既有 handoff 的直接继续控制。输入正确传递与最终语义正确分别记录；结构校验和成功发布不能替代二者。

涉及交接结清变更时，在 QA 和 Research/Page 的真实入口区分尚待真人回答的问题、待确认计划、已回答或明确延后的问题、已完成产物局部修订；核真实未决交接没有被误称已完成，合法修订也不会仅因新建一次调用而被迫再编辑或确认。实际保存或确认后的继续仍应能完成。`none` 发布不等于用户确认，重建设计仍按现有策略完成，不增另一道审批。

用户在 Panel 修改一项标题或描述，加入可识别标记 `E2E-<RUN_ID>`，保存并重新打开核对。随后要求宿主根据这次修改继续；检查来源和实际内容，不能只凭它说“已读取”通过。

### A-FLOW 文件 Worker、脚本与整合

涉及文件脚本接口变更时，核 DSH Producer/Worker 的结构化输入由 Host 写入真实 `script_io.input_file/output_file`，覆盖调用者同名内容；不请求输出时 output_file 为 null，无上下文的原始文件输入和 input_json 保留原格式。验证诊断不得写回产物：只用未引用的隔离 probe 输出路径检查拒写及原文件未变，正常产物操作仍应写入。Companion 原生 Shell 按 Bundle CLI 区分诊断与产物 stdout，不宣称存在 DSH 元数据保护。涉及恢复预览时，核模型可见结果包含实际 preview_token，apply 使用该 token；原有未授权、失效或草稿变化检查继续有效。

```text
请基于已保存功能设计两条独立流程：客户反馈提交与范围确认；
负责人退回补充后重新提交。先确定共同角色和状态，再规划两张 BPMN。
宿主支持时，请将两个独立 BPMN 文件分别交给文件 Worker，
你负责整合、校验和发布。保持已有用户修改，不生成实现代码。
```

核 Producer、真实 Worker 调用及各自精确 `artifact_kind/id/file`，不得让 Worker 写别人的文件或 canonical JSON。检查 Worker 收到的资源入口来自当前绑定 Bundle，必要方法已随任务交付或经实际资源读取取得；仅暴露读取工具、列出路径或返回文件回执不等于方法已读取或产物合格。核 `run_skill_script` 的 BPMN 校验、布局、最终校验结果及 Producer 的整合发布；测试执行者不能在外部替它跑脚本修复产物。系统角色保留稳定 ID `System`，展示名随项目内容语言；结构与最终检查均应接收 canonical `roles` 上下文，核对 stakeholder、泳道和任务类型，不能为英文项目写死中文展示名。

核实际执行入口来自当前项目的 `design_kit/bundles/flow_design/scripts/`，并记录其安装来源与构建身份；不能用开发仓的依赖解析成功替代项目副本的脚本执行结果。涉及脚本分发变更时，先用实际安装候选建立或明确更新隔离项目的执行资源，保留已有设计内容，再复验同一条原生布局路径。布局失败后恢复旧 BPMN 并通过最终校验、发布，只证明恢复与发布成功，不能计为本次布局成功；分别保留各步结果，并核对主对话是否如实说明未完成的操作。

检查两张图均可渲染，canonical 记录指向实际文件，角色/分支符合保存的决定，无队列状态混入设计事实。记录 Worker 返回、父任务最终发布、Git checkpoint；这些不是一个“完成”标志。

沿真实任务、分支和接收方核对业务语义，包含功能详情中的限制，不能只看流程说明文字。已有成图局部修改走定向编辑和最终校验；只有几何变化才需要重新布局，不应为通过结构候选校验而重建整图。比较保留角色/泳道、节点和连线的身份，删除角色不能把其旧泳道 ID 分配给另一角色。多流程修改请求须逐一核对，后续 GRA 不代替发布前的语义整合。

### A-STATE 保存、重开与下一步

关闭再打开测试项目，核 QA 回答、调研报告、功能标记和两张 BPMN。发一个局部修改请求，例如“退回补充时必须保留原退回原因”；检查只修改受影响内容，原 ID、无关记录和用户改动仍在。

要求 Agent 推荐下一步，说明最重要缺口；测试用户明确“本轮够了，暂不扩展页面设计”。核其尊重停止/延后，不为了补满分继续生成。随后完成下方 A-UST、A-KAG、A-GRA 检查。

本轮若生成 Research 结论或整合 PRD，在真实宽、窄阅读区检查报告标题、章节和正文的层级及留白；PRD章节来源在章末查看，核对来源名称、原始来源跳转及切换界面语言后原报告内容保留，不把常驻来源栏或技术ID当作必要正文；报告格式由其模板/契约控制，不以 Panel 样式覆盖产物。角色权限等内容以请求或既定项目写作语言为准；切换界面语言、编辑权限与保存重开不得翻译既有用户原文或把固定中文前缀写回英文内容。

首次生成及更新完整文档时，实际检查正文居中进度和当前执行日志：活动期不同时显示普通空态或“请 Agent 生成”，更新时不把旧报告及旧目录当作当前结果；结束、失败、取消后运行区卸载，报告、缺失、真实读取错误和刷新恢复仍各自成立。

整合 PRD 时核原生执行器使用当前项目 Kit 的 `finalize-html-file`，将已有功能图、BPMN、页面地图、原型、样式预览及白板按相应源文件投影；只有实际存在的来源才要求覆盖。核脚本成功、最终 HTML 校验及实际报告里的配图和来源绑定，不能以普通 schema 发布成功代替。白板 PNG 保留原场景文字、几何和比例，BPMN 保留矢量图；不接受模型重画或测试者替代执行。缺原图、渲染资源或浏览器时，错误留在该操作内，不能接受空图报告或自动下载安装；修复后从原生入口重试，并检查来源栏收起/展开、长来源列表滚动及跳转返回。
脚本输入应包含对应的 canonical owner 索引和产物；已传产物但漏索引时应直接指出缺失文件，不能把空投影计划当作项目没有配图。核查实际脚本退出与写入回执，保留失败后仍发布或自称完成的原生结果；修复输入后从同一入口重试，不靠删除配图或仅有的发布成功消息结案。
PRD 校验脚本从同一 Bundle 的 `reference/prd-template.html` 读取基准；无需模型在参数里重传模板，也不能用改写的 `input.template` 放宽样式或章节要求。缺少该资源仍应在这次操作中明确失败。
修订已有 PRD 时，在原生执行器工作中实际打开报告，核既有 `html_file` 不因重新生成而清空，报告仍可阅读；失败或取消也保留该引用。首次生成仍保持空引用直到最终化成功，两种情况不得混同。
实看长流程图的标签与末端，不能用固定高度把原生文字压成小字，也不能把窄图拉满正文。页面与样式配图按固定桌面布局视口采集完整页面，按 PNG 实际比例自然排入报告；实看超过首屏的页面底部及固定侧栏的中段/底部，核侧栏背景和底部操作沿截图视口正常延伸，正文宽度变化时长图不被压进固定比例。页面内部独立滚动区和折叠内容保留原状态，不把完整页面截图当作所有交互状态覆盖。页面与样式配图须包含源 HTML 完成本地初始化后的主要内容，逐图确认列表、时间线等主体；同轮多个页面各自正常，不能仅凭图数、摘要或静态页头验收。需要选择上下文的详情图应来自当前 canonical 绑定连接，核图中对象与所用连接一致；无选择的诚实空态不代替已有选择的详情投影。仅改变连接选择时旧图也应失效，普通手动预览的空态与 Style 配图仍保留。纯报告样式修订可复用已验收且字节未变的图与来源绑定，以新模板样式和完整源输入校验；源图或投影变化仍需重新完成配图步骤。
只读 `validate-html-file` 不设 `output_file`，其 JSON 诊断不能写成 HTML。核误用拒写时使用未被引用的临时目标，不以真实 PRD 作破坏性探针；同时核正常无输出目标的校验仍成功、文档及图像字节不变。

涉及 DSH 知识查询时，让真实 Producer 或 Worker 用任务相关的有界过滤条件开始查询，无需主 Agent 或测试者预先抄写技术 pin。核返回属于其原生父链选中的项目；翻页或按既定快照续查时使用返回的同一组 pin 与过滤条件。保留错项目、过期快照及项目切换的拒绝结果；首次参数绑定通过不代表知识内容、源文件核验或新鲜度已通过。没有可用索引时正常改读相关源文件，不将查询失败扩大成整个设计任务的门禁。

KAG 的 `due/running/current/failed` 及 GRA 新鲜度、策略等纯状态在正常模型请求的 runtime context 中读取，不排入 `next-step` inbox。沿“先推荐并等我选择”和 Research“仅生成计划、等我开始”路径核真实 turn/step：状态变化不能让已完成的回复多跑一步、虚构用户确认或自行调用 Bundle/搜索；空闲时也不能唤醒模型。下一个正常请求应读到最新状态，项目切换不得带入旧项目状态；界面的 KAG 进度、终态和既有刷新仍正常。真实 Panel 保存反馈、开始动作和建议接受后的续作分别按原入口验证，不能一并停用。

`source.kind` / `form` / `summary`、正文里的真实授权和后续实际工具调用；
内部完整指令与 action receipts 不应成为用户撰写的普通长气泡，也不应被主 Agent
当作需要向用户解释或确认的技术细节。通知入队不等于执行或保存完成。

不读取 `source.summary` 作为标题。若只看到“收到执行请求”，应将业务摘要展示记为
`NOT_MET`，即使原生摘要元数据已保留，也不能称 UI 全部通过。源码预览必须核实际
唤醒消息投影；直接挂载支持摘要的非唤醒 `ContextInjectionRow` 不能验证这条路径。
不要改用不唤醒的投递、伪装其他来源或复制宿主 UI 来掩盖该限制。

投递失败时接受记录不得回滚。保持审阅界面打开时，应保留核对原对话和显式重试的路径；
重开界面后的恢复能力另核，不由当前挂载状态下的重试推断。重复点击、轮询更新和已入队后
返回错误不得重复唤醒，拒绝或延后仍不唤醒。

核验修复方向：明确用户决定和现有约束不能被下游生成内容反向覆盖；不能靠改掉约束或只添注释来掩盖仍可执行的违约路径。已接受且复核成立的确定性修复应直接进入正常执行，不再次请求相同批准；真正缺少新决定时仍停在用户输入关卡。

接受续作需要选择处理方式时，核原生 Agent 使用 `design_read_review_action` 返回的当前日志 `revision` 和项目绑定 `selectionRevision`，没有把建议输入的设计版本当作日志版本。日志冲突应带出预期值与当前值，让 Agent 重新读取、复核后沿原接受收据继续；等待或反复传旧值不能解决冲突。长建议和候选目录仍须保留完整内容，同时当前调用身份及收据应在返回前部可读。保留真实冲突历史，不重新接受、不清日志；分别记录无需执行的选择和实际 Bundle 修改结果。

核实际接受通知到执行入口的完整衔接：原生 `run_design_skill` 应领取该建议的精确执行凭据并进入正常 Bundle 执行，不能因通知来源是插件而再次要求人类启动。记录 claim、Producer/main 进入和实际保存，不能以工具 `isError: false` 或通知已送达代替成功。若首个 Owner 只完成部分修复，主 Agent 在同一尚未结束的接受处理轮内，应能以普通调用补齐同一项目、精确 Kit/Bundle 及版本的原修复目标；沿实际首调用和项目 Journal 复用原授权，不再要求接受，也不重新领取已完成凭据。轮次结束或进入新轮后不能仅凭旧接受记录启动普通续作。若先前执行失败，沿原凭据重试并保留逻辑执行身份，不重新接受或伪造消息来源；普通通知、未领取的建议、错目标/版本及显式重放已完成凭据仍不能启动执行。已有交接下的新修订不能被当作采纳旧保存；独立的“继续”动作仍遵守原有人类控制。

审查深度或上下文投递发生修改时，在上述 GRA 路径内检查：

- 中英文设置显示当前设计／关联设计／整个项目三个范围（保留内部 `light/standard/thorough` 值），刷新后仍保留；切换范围不擅自开启自动审查。普通设置弹窗只有取消与保存：取消或 Escape 不落盘，保存直接生效且不启动审查、不新增主对话消息，失败保留选择并可恢复。关闭模式下才在模式选择下显示对其他功能无影响的说明。
  将时间输入清空后切换模式，再保存；只校验当前可见的时间项，隐藏时间草稿不阻止关闭或另一模式的保存，也不覆盖其已保存数值。关闭模式的范围滑块灰显禁用，重新开启仍保留原范围。
- 手动审查沿当前宿主实际支持的原有调度或原生工具入口，与保存设置分开；不再要求点击已移除的“保存并检查”。保留原调度负面检查：服务已接受但响应丢失时，同一逻辑请求的重试保留原身份和范围，只产生一组评审；更改设置后再次请求使用新身份，切换项目或会话不串用旧请求。已完成或已在处理显示对应状态；业务拒绝与传输结果未知均不得转为普通 prompt。未提供直接调度能力的宿主仍验证原有原生 Agent 协调及前台执行确认边界。
- 原生请求实际携带所选范围、停止条件及固定证据版本。调查起点必须来自该版本中实际存在的文件；旧 Journal、未保存的文件及缺失定位不能冒充本次变更或已审查内容。起点不是排他清单，重要已知风险仍可继续追查。
- 分开检验两个变量：强度变化比较实际读取文件、范围、轮次和发现；投递优化在相同深度、证据、模型及宿主配置下比较重复输入、输出及 usage，并检查原有问题是否仍能发现、必要依据是否可取回。分别报告缓存输入和非缓存输入，不能把少查资料、字符数或建议数直接换算为无损效果或费用降幅。
- 接受建议后须通过现有详情读取取得完整内容；重复状态不新增相同 inbox 全文，项目切换及重启后仍能取到当前状态。后续审查应收到已保存的处理选择、理由和执行状态，不能把有理由的 `no-action` 还原成尚待回答的问题；若再次提出，须说明改变原理由的新事实或用户重新考虑的要求。分别验证历史实际投递与结果是否尊重处置，不能只凭任务成功结束判定质量通过。DSH 保存新 checkpoint 不应仅因评估身份变化而重注整段系统规约。

复用同轮的原生请求和保存路径，不为这些检查再做无关全产品扫描。提示词断言或脚本模型仅证明指令和工具边界，不能替代真实宿主的取证行为与效果验证。

GRA 无后台能力时不能静默切同步。只在用户明确选择后测试一次前台回退，并把“回退路径通过”和“后台运行未覆盖”分别记录；不能用回退结果满足原生后台覆盖要求。触发建议后只读比较 Design Files 与原 checkpoint，系统评估/审查记录变化不算擅改设计。

选取当前仍有效的建议，延后后重开项目，核主 Agent 的实际上下文保留 `deferred`，不再强制把同一建议列为下一步选项；用户主动重新处理仍可读取、接受和续作。已被更新审查替代或因来源变化不再可见的历史建议不能用于证明此路径。界面的未处理数量可以包含延后项，不能仅凭这个数量判定决定丢失。

涉及建议历史去重时，保留实际失败历史和原始反证复验，不能清空历史制造成功。核对独立审查实际收到的是定位、来源版本、处置和后续选择/理由/执行状态，不包含旧机器诊断或修法全文；原始完整建议仍应可经现有详情工具读取。审查须从当前固定来源独立判断，不能因历史涉及同一对象而漏报，不能把已接受但未执行视为已修复。仍有效的拒绝或无需处理理由应被尊重；改变其判断时须说明当前证据、用户重新考虑或有来源依据的纠正。精确重复由 Journal 原子发布过滤，措辞不同的语义重复不承诺被过滤，不能用扩大过滤掩盖真正纠错。复用同一修复链验证审查、接受后核实及正常 Bundle 保存，分别记录；空建议列表或修复成功都不能单独证明审查质量通过。

KAG 视觉同时抽查：默认文字密度、定位/搜索/选择/退出、明暗切换、2D/3D 切换与工具可用；切为英文时数量文案和标识匹配说明随界面语言变化，既有业务原文保留。画布操作前后设计文件不变。详细颜色和布局回归复用现有浏览器测试，不在每次业务脚本中重做全套视觉评审；布局或触发器探测通过只证明该项探测，不能代替实际交互验收。

## C：Studio 创作、保存消费与导入导出

从当前宿主入口在独立 tab/浏览器打开 Studio。只在新建/编辑 Kit 或 Bundle 时出现 AI 对话；保留外层导航、顶部信息与内部文件导航。下面所有 AI 修改必须通过屏幕上的聊天输入交给真实宿主，测试 Agent 不能改文件代演。

先从已安装 Bundle 卡片“打开→面板预览”核左侧原始 `panel.yaml` 和右侧真实只读样例；不能通过新建、复制或编辑副本绕过安装原件路径。预览本身不创建库记录、不修改原件；缺来源、无样例或无预览能力时明确说明。涉及共享渲染器变更时，确认 Studio UI 和宿主 Studio consumer 也使用当前正常构建，不能只核 Core/Panel。

### C-BUNDLE 独立创作与持续编辑

1. 复制 `business_rules` 为本轮独立 Bundle；再从空白创建一个最小 Bundle，检查创建、打开、复制、编辑各自语义。不要修改已安装原版。
2. 在编辑聊天框发送：

   ```text
   请先读取此工作副本的创作方法、输出契约和已安装组件说明。
   把当前规则面板明显改为卡片列表配合选中详情的表达，突出规则标题、
   条件和结果；使用现有共享组件，保留已有记录 ID 和字段语义，
   不为了演示增加无业务依据的状态或其他填写字段。
   准备源码修改并让我预览审阅，不要自行保存或发布。
   ```

3. 核宿主实际可读创作技能、组件契约与当前副本，拥有受限编辑工具；看得到真实执行、候选 diff 和面板变化。测试者不得通过 Chrome 或 shell 替宿主生成候选。
4. 原始文件在“编辑/diff”之间切换；面板预览左侧 `panel.yaml`、右侧实时渲染，共享同一份候选状态。全局保存/还原作用一致；无效 YAML 有明确诊断，不能错误显示已保存或已验证。预览有脑图等图形视图时，实际切入并操作缩放、适配画布和记录详情；检查按钮图标、节点与连线的位置和尺寸，不能以图形 DOM 已存在代替样式验收。保存后退出并从库中重新打开，也须从只读预览切入图形，再返回详情并重入，核对节点与连线仍可见；未保存候选的图形成功不能替代这一检查。
   若预览使用 `structured_data.read_fields`，在同一路径核对双语字段名、具名列表项、目标名称与原ID、未声明字段及折叠内容；展开/切换语言后原始JSON应保持不变。缺少引用目标时显示原ID，不以隐藏事实代替修复。
5. 先还原一次候选，核未写入；再请求修改。人工编辑一个可识别文案后，通过全局保存，关闭重开，核源码与预览保留。
6. 第二轮聊天只修改一个局部，并明确保留刚才人工修改；再次保存重开。核原生 Agent 读取当前副本内容，无旧候选覆盖新修改。
7. 空白 Bundle 补齐真实方法、schema、validation、面板和预览样例，验证可保存、预览、重开；不以仅能保存不完整草稿代替可用内容。

### C-KIT 新建、挂载与编辑

1. 新建 Kit，编写 Mindset，挂载上一步 Bundle 的稳定身份；再复制一个已有 Kit，确认复制独立、原件不变。
2. 核“原始文件/挂载管理”切换，Kit 不显示一个虚构的 Bundle 面板。挂载管理左右分栏，已挂载项不重复出现在备选中，搜索仅过滤备选；添加、移除、保存、重开后声明与显示一致。
3. 通过 AI 对话修改 Kit 方法，再人工补一处文案并保存；第二轮对话读取这些改变。核挂载身份保持不变且读取该 Bundle 当前已保存内容，空 Kit 与有效可执行 Kit 不混淆。
4. 宿主断开时保留输入/未保存内容并提示连接问题；仍可使用的手工编辑要可达，不虚构 AI 成功。断网后人工编辑源码并尝试保存，检查错误对话框的“重试读取”；离线重试失败不自动重弹。已有待保存候选的断网保存若进入“保存结果待核对”，恢复连接后使用“核对保存结果”：不得要求丢弃草稿，未提交时保留内容供明确重试，已提交时核对实际文件后才标记保存完成。读取或准备失败时，恢复连接后不改变草稿文字，重试读取再明确保存；已确认写入的分支不再次保存。核对未发送聊天跨断开、重试和保存仍保留，且未自动重发写入或聊天。取消离开应保留输入，再从另一正常标签页重开核对已保存源码。显式确认放弃后的聊天恢复不属于此项；未测试的页面关闭后聊天恢复不得写成通过。通过正式入口恢复宿主上下文后再继续 AI 修改。

### C-ARCHIVE Bundle 和 Kit 分别往返

对独立 Bundle 和含挂载内容的 Kit **各做一次**“保存 → 对象的 `…` 菜单导出 → 隔离接收环境选择文件导入 → 成功提示 → 打开/重开”：

- 在装有完整合法资源 Bundle 的宿主中导入一个很小的无关归档；目录和重名检查只依赖已加载元数据，不应完整捕获所有安装来源。具体选中来源的复制、编辑、校验和导出仍检查完整字节，并把真实失败定位到该操作；不得靠过滤来源或降低来源一致性校验补成通过。对合法的大资源来源，分别核对 32 MiB 原始内容与 64 MiB 归档 JSON/ZIP 边界、内存/落盘资源投影及保存重开的一致性；二进制原字节保留，不解码为正文。归档上限按其自身 UTF-8 字节计算，不把宿主 RPC 包装或转义量当成归档内容；通过实际接口分别核对上限与超出一字节的结果，传输成功也不能代替归档读取成功。
- Kit 与 Bundle 各自列表的新建按钮旁提供“导入”，点击直接选择文件；相邻菜单可选择文件夹。取消选择不改变内容，导入成功刷新当前列表并提示成功，不增加归档页。
- 单独核验普通点击能打开系统文件选择窗口，并能取消后再次打开。自动化工具直接填入文件只证明上传处理，不能替代这个检查；文件选择拦截应限于可关闭的测试标签页。交还页面前解除拦截，或在同一测试环境的新标签页重新验证普通点击，避免留下按钮无响应的测试状态。
- Bundle 分别覆盖普通 ZIP、文件夹和裸 `SKILL.md`；只有 `SKILL.md` 是导入必需文件。缺少其他定义文件时保留为本地副本，提示缺项并可选择“AI 补齐”或“暂不补齐”。后者保留卡片“待完善”提示；前者进入原有编辑模式，聊天框带入缺项上下文，用户正常发送。不得实现另一套补齐会话或写入流程。
- 普通 Skill 的导入单位是完整目录，`SKILL.md` 仅为识别入口。用包含 `references/`、`assets/`、`scripts/` 的样本检查 ZIP 和文件夹导入；嵌套路径、相对引用、文本和二进制文件都应在保存、重开和导出后保留，不按 Bundle 定义文件白名单裁剪，也不凭空补造来源没有的附件。
- Kit 的核心文件是 `mindset.md` 和 `kit.yaml`；挂载问题在已有挂载管理中修订。选择错误类型、缺少核心文件或无法读取的 ZIP 时明确提示，允许重选，不虚构成功。
- 编辑模式中人工新建一个文件，通过全局保存、关闭重开核对；再让真实宿主 Agent 新建另一个文件，核相同文件树、diff、预览和保存流程。完整与待完善副本都可新增文件。补齐定义后重新读取，卡片警告应消失；不能把可保存草稿当作完整定义。
- 导出位于本地副本及已安装内容的 `…` 菜单，点击直接下载 ZIP，不填写来源或许可证，不检查是否存在许可证。已有随包文件照常保留；未发送对话和正在编辑的内容不丢失。
- 下载文件应可用普通压缩工具打开，保留可读的中文文件名及完整源文件；检查实际文件名、ZIP 签名和内容，再用实际下载文件导入。浏览器开始下载不等于已保存到磁盘。旧 JSON 导入的兼容检查单列，不替代 ZIP 往返。
- 导出当前已保存内容；未保存的源码、名称、挂载选择和 AI 建议保留在原编辑器，不要求先保存或还原，也不声称导出包含这些草稿。实际下载后核对其字节与已保存内容一致、草稿仍在；在途或结果待核对的保存继续保护一致性。已安装独立 Bundle 可直接导出其当前完整内容，不应先创建副本或要求包含它的 Kit。
- 同名重复导入自动重命名新副本，不覆盖已有内容。比较方法、schema、面板、语言资源、二进制/附件和随包挂载内容；身份投影之外的原始内容应保留。UI 名字相同不能代替源码核对。
- 接收环境不借用作者工作区或安装路径；Kit 可解析其实际挂载内容。完整 Bundle 正常挂载后，通过宿主入口运行一次小任务、展示 Panel、人工修改保存后重开。不完整导入与完整可运行内容分别记录。
- 查看 Bundle 卡片的 Kit 数量标签，点击即查看挂载；不再显示重复操作。检查入口、忙碌/成功/失败反馈、按钮、菜单和弹窗沿用共享样式。

### C-CURRENT 保存消费与项目隔离

在原有编辑器完成一次普通保存，随后通过真实宿主 Agent 使用该 Kit/Bundle。
不要求发布、升级内容版本、选择 latest 或重新挂载。源码保存成功、样例预览成功、
原生 Agent 实际读取和运行成功分别记录，不能互相替代。

1. 在库中直接编辑同一 Bundle，保存后再打开应为相同身份；显式复制后修改副本，原件不变。未完成文件可保存，实际预览/执行所需内容缺失时给出具体诊断。
2. 用 Kit 创建项目，核 `design_kit/kit/` 与 `design_kit/bundles/<identity>/` 包含完整方法、schema、校验、Panel、语言和资源；宿主从这一份读取。
3. 修改库 Bundle 后，新项目取得新内容，已有项目仍使用原项目文件；关闭重开后结论不变。
4. 让 Agent 用普通文件编辑更新已有项目中的一个定义，保留用户数据与自定义；后续读取/调用使用新文件。检查真实并发冲突，不增加单独升级流程。
5. 旧项目没有项目定义树时，只能从其真实保留的内容初始化；缺失来源应报告，不能用当前库伪装恢复。从已有面板的项目切换到缺源项目后，核实际绑定、可见页面的项目标题及只读恢复提示均指向新项目，不能继续显示旧项目的面板冒充已打开。冷重开须先确认原生 Host 恢复的是原会话，再核该身份与缺源诊断；直接调用工作区读取不能替代此前的 Agent 激活事件链。缺源或派生知识恢复失败的会话仍应能关闭项目或切到正常项目，不能将未获得的知识运行态当作必须先释放的资源；真实持有其他项目资源的冲突仍须报告。正常项目冷启动后首次提示词应使用其当前 Kit。普通续作、保存仍须遵守原始项目定义的保护，不能因只读投影可见而绕过。

这是当前内容模型的验收，取代本地内容版本发布要求；产品 npm 发布仍走现有 GitHub Actions。

## P：发布后实际 npm 安装与抽查

本段只在产品已经通过正式 GitHub Actions 发布后执行，不触发发布、不本机 `npm publish`。步骤遵循该精确发行版本随包的[宿主安装指南](../../packages/companion/HOSTS.md)及[开始使用](../wiki/getting-started.md)，不要复制另一版本的内部命令。

### P0 固定 registry 事实与抽样选择

记录 registry 返回的 `yugoo-design@<RELEASE_VERSION>` 元数据、`dist.integrity`、依赖版本及 `latest`。从 npm 下载实际发布包，核其与 Actions 制品身份一致；不能拿本地 tarball、源码链接或构建目录代替实际 npm。若已经有更新正式版，记录当时 `latest`，不要为了测试将标签回退。

在业务复跑**之前**确定一条链路和执行环境：

1. 优先本次改动直接涉及、修复过失败或上次未覆盖的链路；出现高风险变更时不能随机避开它。
2. 风险相当时优先轮换最长未测链路；仍相同时，可对候选 ID 的固定排序以 `RELEASE_VERSION + SOURCE` 为种子做可复现抽选，记录算法、种子、候选和结果。也可记录负责人的显式选择；“随机”不是强制要求。
3. 选择运行在全新安装或升级后的环境，记录原因；两个环境都必须做下列安装基本检查，至少一个环境完成所选业务链路全部检查点及前置条件。
4. C 若仍有未通过的保存消费或项目隔离项，仍如实报告，不得换抽一条更容易通过的来掩盖。抽样失败先修复/报告，不靠换样本凑成功。

### P1 从零安装

使用没有 Yugoo 登记、runtime 或开发源码依赖的独立宿主 profile，并隔离 npm 缓存与安装根。允许复用受支持的 Node 与完整模型缓存，但记录复用范围。

把正常安装提示词交给该宿主 Agent，明确只安装 `RELEASE_VERSION`。核 registry 包获取、安装文件、版本与摘要、宿主注册/导入、激活/必要重启、实际服务加载路径分别成功。确认无需开发机私有路径，默认 Kit 与创作资源可读；创建一个小项目，打开 Panel，编辑保存后重开。检查模型准备状态与可用能力，不把下载失败掩盖为全部可用。

从用户实际复制的官网/通用提示词开始，核对包获取与宿主适配是否分成清楚的两步；所选宿主的提示词应直接包含接入、人工激活及验证步骤，而非只更换文档链接。确认 Agent 优先使用所获取版本的 README 与 CLI 帮助，按实际系统、架构和 shell 准备环境；只有随包说明未解决的具体问题才查在线指南，并记录原因。缺 Node 时应给出并完成依赖准备后继续，不能仅以缺依赖或历史测试平台结束安装。若宿主需要手动导入套件或 MCP，核对交接是否包含准确的界面位置、本次生成的文件/配置及操作后的继续步骤；完成后必须实际调用工具。千问办公优先发现并使用当前原生连接器操作，必要时再由用户导入；若当前任务未获得新工具，按宿主提示新建任务再核验，不能用 Skill 已加载代替 MCP 已连接。原生 GUI 身份识别、MCP 连接、Hook 投递、模型执行和保存后消费分别记录，不相互替代。测试记录分别标明制品准备、宿主导入、工具可用和原生设计使用的结果；没有对应机器/宿主时，明确记录未验证。

显式指定 npm registry 时，核对宿主安装前的元数据查询与实际依赖安装都使用该源；仅最后一条安装命令带有镜像参数不能证明前置查询同源。安装耗时区分包获取、原生安装、模型准备及人工操作等待，不把下载预算或其他机器的耗时当成当前用户的实测归因。

普通 pnpm 路径使用默认依赖布局和脚本策略，确认取得的正式包已包含预构建 Node/CPU 运行闭包；不能靠 `ignore-scripts`、`approve-builds`、手改 `allowBuilds` 或源码构建把检查补成成功。记录源包/完整性、下载量、冷缓存与复用范围，分别核查原生 CPU 推理、图片运行依赖及数据库加载。Linux、Windows、macOS 的结果分别记录，不能跨平台代证；轻量依赖探针不能替代本节真实 Host 安装及设计使用。旧版归档的原生修复事实保留，不能改写为本轮无干预成功。

安装闭包检查的物理目录不能有包含 `node_modules` 的祖先目录；隔离 `HOME`、`NODE_PATH` 不会阻止 Node 向上查找依赖。使用满足此条件的新临时目录，记录实际依赖解析路径，并排除继承的安装脚本开关（包括 `ONNXRUNTIME_NODE_INSTALL_CUDA`）。预构建依赖应由制品组装时明确移除自动安装脚本，并保留来源与清单变更记录；不能假定 bundled dependency 不执行安装脚本。模型缓存复用与用户项目/profile 的隔离仍按上文执行，无需复制整套开发环境。

### P2 从上一正式版升级

在另一独立环境先从 npm 正常安装 `PREVIOUS_VERSION`，创建并保存一个项目和可用的 Studio 副本。记录内容、ID、Kit/Bundle pin、配置与来源摘要；旧版本没有 Studio 副本能力时记录事实，不伪造旧数据。

经同一宿主的正常更新路径升级到 `RELEASE_VERSION`，完成要求的原生导入/重载/重启，核**实际运行**的新版本，而不仅是下载目录。打开原项目和旧副本，核用户数据、身份、固定内容引用仍正确；执行一次局部修改、保存重开。确认失效旧进程/旧路径没有继续接管请求，Node 选择与宿主连接正常。不要“先清空数据再升级”，也不要通过手改 manifest 或移动包伪造升级成功。

保留旧内容库时，再创建一个空项目并正常选择安装 Kit；同名同版本的历史 Bundle 快照不得覆盖当前安装来源或导致路径拒绝。分别核安装源预览、已保存 Studio 编辑的新项目消费及旧项目定义隔离，不清空历史来绕过失败。安装源的 Kit 与独立 Bundle 预览均须接受普通图片、字体等不透明资源，保留其字节，不把它们当作 UTF-8 定义读取。

DSH 的旧版若由官方 CLI 或插件页安装，或者曾按宿主提示修复后启用，可能没有成功的 Yugoo 安装器收据。正常升级应读取当前实际安装和配置继续，不要求补造旧收据或再次取得已有升级授权；可选旧收据的历史核验不能代替当前状态与并发变化检查。保留先前失败及修复事实，分别验证本次升级的实际执行和数据保存。

### P3 至少一条业务主线完整复跑

在 P0 选定的新 npm 环境执行 A、B、C 中至少一条，使用新的 `RUN_ID` 并保留实际原生证据。A/B 的 UST、KAG、GRA 检查仍必需，C 的 AI 第二轮、Kit/Bundle 两种归档及保存消费、项目隔离项不能缩成一个页面 smoke。另一安装环境保留 P1/P2 最短保存重开证据即可。

发布后结果应写成“全新安装：…；升级：…；抽查链路/环境：…；未覆盖：…”。发布成功不意味着 P1/P2/P3 成功；失败影响安装或数据时及时向发布负责人报告，不能因版本已上线而关闭测试。

## 结果记录、维护和复用

每轮在现有任务证据目录保存一份结果表，不新增产品运行状态或持久化 authority：

```text
run: <RUN_ID>; playbook_commit: <SHA>; source/artifact: <SHA/version/integrity>
host/platform/model-route: <no secrets>; roots: <owned locations>
phase: development | release-candidate | post-release
sampling: <candidate IDs / reason or seed+algorithm / selected chain+environment>

checkpoint | status | functional | UIUX | expected | observed | evidence | next action/owner
A-QA       | ... | ... | ... | ... | ... | ... | ...
B-MIGRATE  | ... | ... | ... | ... | ... | ... | ...
C-CURRENT  | ... | ... | ... | ... | ... | ... | ...
P1/P2/P3   | ... | ... | ... | ... | ... | ... | ...

UIUX: <visible entry / steps / screen inspection / findings / fix+recheck / untested>
search preflight: <plugin version+path / selected providers / native search+read evidence; no secrets>
usage, when measured: <normal/auxiliary calls; cache/non-cache usage; unknown usage; context/output/compaction settings; timing limits>
summary: passed / failed / blocked / not-run IDs; retained failure evidence
scope decisions: <who/when/what; no silent omissions>
reuse: <prior run+checkpoint, identical inputs/artifact/environment, why unaffected>
cleanup: <owned processes/ports/paths, consumers and cleanup conditions>
```

功能和 UIUX 分别使用本剧本的结果状态；纯后台检查的 UIUX 可注明不适用及原因，不能用不适用掩盖用户可见入口。展开实际执行阶段的全部检查 ID，包括 A/B 各自的 UST、KAG、GRA 和 GRA-ACTION，不能只填以上示例行。每项至少保留关联的原生调用/运行结果、持久数据或 checkpoint，以及适用的 UI 截图/录屏；不需要复制整份宿主会话或模型隐含推理。证据必须可定位并脱敏，不含 token、真实客户资料或模型认证。

监测先按任务归属和文件元数据发现变更，仅顺序解码相关变化日志；复用已取得的未变记录，不在每次轮询重新解码并同时保留全部历史会话。监测自身的资源开销和操作失败单独记录，不能当作产品泄漏或模型耗时。

产品入口、执行策略、handoff、迁移契约、创作/归档接口或安装路径变化时，同一开发任务必须同步更新本剧本的操作和断言。保留稳定检查 ID，新增机制补对应检查；废弃步骤注明替代项和原因。修复真实缺陷优先添加到对应已有自动回归，并在本剧本保留用户可观察的检查，不能用放宽预期消除失败。

自动测试为定位和复用提供辅助：现有 `test:shared-panels`、Panel `test:graph` / `test:graph:browser`、Studio source-candidate/content-archive、DSH authoring、项目迁移和产品安装检查各有边界。按[开发指南](../wiki/development.md)读取当前 package scripts，构建依赖后运行需要 `lib` 的检查；源码别名测试不证明安装包可用。剧本不是一条调用这些测试就自动获得真实 Agentic PASS 的总命令。
