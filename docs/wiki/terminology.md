# 命名与术语翻译规范

本页统一语构设计系统（Yugoo Design）的产品名称和中英文术语，供 README、Wiki、使用指南与贡献文档引用。概念职责见[核心概念](concepts.md)，文档维护与公开同步见[公共文档同步规范](../public-document-sync.md)。

## 产品名称

- 英文名称：**Yugoo Design**，保留大小写与空格。
- 中文名称：**语构设计系统**。中文文档使用 **语构设计系统（Yugoo Design）**，保留英文品牌，方便识别与检索。
- 需要强调多维度思考、细节推敲与完整方案时，使用“**构思设计**”，描述活动和用途。
- 维护团队署名保留 **YugooDesign Team**，个人署名与权利声明遵循 [NOTICE](../../NOTICE)。

例如：

> 语构设计系统（Yugoo Design）是一款兼容主流 AI 智能体（Agent）应用的交互式构思设计插件。

## 中文在前，英文在后

中文文档中的产品名称和核心术语采用 **中文（英文）**，使用中文全角括号。首次介绍某个术语时给出完整对照；独立阅读的页面、术语表和概念定义也要提供对照。同一页面已经解释过的术语，可以按上下文使用中文简称或已说明的英文名，避免连续重复影响阅读。

正文不逐词翻译普通叙述。英文文档保留英文名称和术语，与中文版本保持相同含义、能力范围和状态。外部产品使用其官方名称；没有确认的中文译名时保留英文，不自行创造品牌译名。

## 核心术语

| 中文（英文） | 使用说明 |
| --- | --- |
| 设计套件（Kit） | 一个领域的方法与能力组合，包含领域主提示词及挂载的设计技能包；用“构思设计”说明其支持的活动。 |
| 设计技能包（Bundle） | 聚焦一个设计维度，组织专业方法、结构化成果、校验、交互面板与执行声明。 |
| 领域主提示词（Mindset） | 提供领域方法、判断依据与能力选择引导；是套件的一部分，不等同于整个套件。 |
| 智能体（Agent） | 在宿主中使用模型与工具、推进任务的执行角色。 |
| 智能体技能（Agent Skill） | 专业方法的技能入口；与增加交互、校验和执行控制后的设计技能包区分。 |
| 智能体宿主（Agent Host） | 管理会话、模型、凭据、工具与呈现能力的应用。 |
| 设计项目（Design Project） | 保存设计文件、相关产物、版本记录及自身 Kit/Bundle 定义的独立项目；来源记录用于追溯。 |
| 设计文件（Design Files） | 保存独立设计事实与产物的文件；整合文档与状态摘要另按派生内容处理。 |
| 设计面板（Design Panel） | 用于查看、交互、修改与保存设计成果的界面；简称面板（Panel）。 |
| 信息切片（Information Slice） | 对一个可独立推敲的设计维度的比喻，例如功能、流程或规则；不是新增文件格式，也不要求每个 Bundle 都配置面板。 |
| 缺口驱动循环（Gap-driven Agent Loop） | 根据当前目标、证据与未决问题持续选择有意义的行动；正文可写“缺口驱动推进”，不等于补齐所有字段或固定运行全部 Bundle。 |
| 清晰度评估（U/S/T） | 理解度（Understanding）、结构化（Structure）、可验证性（Testability）的启发式判断，须结合证据、当前范围与版本理解；不是客观完成率、阶段门槛或跨 Kit 排名。 |
| 设计工作室（Studio） | 套件、领域主提示词与技能包的查看和管理入口，创作能力按安装版本描述。 |
| 工作副本（Working Copy） | 可编辑的方法与面板源码；当前内容可原地保存，显式复制才产生独立身份，保存不等于 npm 发布或改变已有项目。 |
| 固定版本引用（Pin） | 来源或旧格式项目记录的精确身份与版本，用于追溯和原内容恢复；不代替完整文件，也不是本地保存的发布门禁。 |
| 知识图谱（KAG） | 本项目关联独立设计来源与产物的知识能力；保留已有缩写，不另造英文展开。 |
| 主动审查（GRA） | 本项目从一致性、知识疑点与待澄清意图三个视角提出建议的能力，执行范围取决于宿主。 |
| 产品需求文档（PRD） | 汇总应用设计的派生交接文档，不重新成为独立知识来源。 |

审查视角首次出现时可写“一致性审查（Grounding）、知识反思（Reflection）、意图对齐（Alignment）”，随后说明具体职责。这是本项目语境中的解释，不能仅凭译名推导新的功能或保证。

**A2UI** 保留协议名称，首次出现时解释其用途，例如“由智能体生成交互界面的 A2UI 方案”；不把所有交互面板都称作 A2UI。Git、Node.js 等技术名称也保留原名。

## 文案与技术标识的边界

词汇翻译用于说明与展示。命令、工具名、包名、目录、配置键、协议字段和版本标识保留实现中的准确拼写，不按中文译名替换；代码块中的命令必须对应文档所描述的版本。

套件选择的用户动作应描述为“选择或启用设计套件”，规范子命令使用 `kit`。项目操作以 `migrate` 表达“迁移已有设计项目”，以 `reconstruct` 表达“从材料还原设计”；当前操作指引不推广旧别名。文案须与对应版本的实现一致，不能把尚未发布的源码命令写成旧安装版已经可用的步骤。

新建项目附带的说明、安装后的技能引导与界面文案也应按本规范核对，但它们需要在各自维护源中更新；修改 Wiki 不代表运行时模板已同步。历史证据、引用原文及第三方声明保留来源；当前说明中的名称更新不改写历史记录。

维护译名时，同时核对中文 README、英文 README、核心概念及相关指南。通过现有导出策略同步正式文档，不在公开目录维护第二份词表。
