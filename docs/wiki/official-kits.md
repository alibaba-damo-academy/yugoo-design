# 使用官方设计套件（Kit）

语构设计系统（Yugoo Design）的设计套件（Kit）将一个领域的方法与设计技能包（Bundle）组织在一起。本页帮助你判断从哪里开始、在面板中看什么，以及什么时候可以交付当前成果。精确版本、获取地址和随装范围统一见[官方套件清单](kit-sharing.md#official-kits)，安装先看[开始使用](getting-started.md)。

| 你想完成的事 | 套件与状态 | 主要成果 |
| --- | --- | --- |
| 设计软件应该怎样工作，包括应用中的 AI 能力 | Web App Kit | 功能、流程、规则、数据、权限、原型及整合后的产品需求文档（PRD） |
| 了解资源分配、排班等业务问题的建模方法 | 决策与运筹建模（Decision Modeling）Kit，暂仅内部验证 | 以下保留业务定义、样例数据、数学模型与结果比较的方法示例；当前不作为可选的已交付套件 |

一个设计项目（Design Project）选择一个 Kit，并保留它的精确版本。Kit 中的 Bundle 是可按需调用的能力；下面按问题介绍它们，不要求逐项执行。

## Web App：从业务想法到可以讨论和实现的应用设计

以六人设计工作室为例：客户需求和反馈散落在聊天中，修改经常影响交付。你希望设计一个项目协作平台，让 AI 整理反馈、提示影响，项目负责人决定范围与交期。

开始时准备你知道的实际情况即可：谁使用、哪里经常出问题、这轮想改善什么；已有文档、截图或原型可以交给宿主智能体（Agent）参考。还没有想清楚的部分可以保留未知，不必先写出完整 PRD。

### 根据当前问题选择设计活动

| 现在需要想清楚什么 | 对应能力 | 你在结果中判断什么 |
| --- | --- | --- |
| 目标、使用者与第一版边界 | 智能提问 `smart_questions`、调研 `research` | 哪些背景属实，哪些假设需要查证，哪些问题本轮暂不解决 |
| 应用包含什么、哪些事情值得优先做 | 功能模块 `function_modules` | 客户反馈、范围确认、交付审阅等能力是否必要，例外是否被照顾 |
| 一次请求怎样经过人和系统 | 业务流程 `flow_design` | 谁处理、谁确认、不同条件走哪个分支，异常后如何继续 |
| 系统需要记住什么、怎样判断和约束 | 业务数据 `business_data`、业务规则 `business_rules` | 反馈、交付物、变更之间的关系，以及确定的业务处理规则 |
| 谁可以看见、修改和承诺什么 | 角色权限 `role_access` | 客户、设计师、负责人之间的操作与可见范围 |
| 应用里的 AI 应该怎样参与 | AI 能力 `ai_agent_capabilities` | AI 的职责、输入输出、提示词、Skills、工具与协作关系；哪些取舍仍由人决定 |
| 如何接入外部能力并通知相关的人 | 外部集成 `integration_design`、通知设计 `notification_design` | 连接对象、交换的信息、失败处理、通知时机与接收者 |
| 用户实际上怎样看见和操作 | 视觉风格 `design_style`、页面设计 `page_design` | 视觉方向、页面关系、具体控件与原型路径是否符合工作方式 |
| 如何检验和交接当前设计 | 质量验收 `quality_acceptance`、PRD 整合 `web_app_prd_assembly` | 行为是否有可观察的验收依据，整合内容是否忠于原设计 |
| 需要先共同探索一个想法 | 自由白板 `whiteboard` | 图形、文字与关系是否帮助你理解和表达问题 |

设计面板（Design Panel）把这些成果呈现为图、卡片、表单、表格或原型。图与详情编辑同一份数据。你可以直接修改确定的内容；需要解释、比较或调整关联设计时，在对话中指出对象与原因。

### 一个适合开始的请求

```text
我们是六人的设计工作室，客户需求和修改意见散落在聊天里。
我想设计一个项目交付平台：AI 帮忙整理反馈、提示影响，
范围和交付时间由负责人决定。先帮我把一次客户修改请求展开成
可以讨论的流程，结合具体情境问我真正需要决定的事。
本轮先不做合同收费和财务管理。
```

完整练习见[工作室项目交付案例](web-app-demo.md)。你也可以直接请求功能、数据或某个页面；明确的结果请求不需要先完成全部访谈。

### 什么时候可以结束这一轮

当这轮关心的操作、规则和重要例外已经能被你理解和判断，就可以整理当前设计、未决问题及来源。PRD 是已有设计的整合输出；某一开发任务需要更精确说明时，再按[设计到开发交接](../design-development-handoff.md)准备任务级 spec。原型可交互不等于业务服务已实现，设计工作也不要求填满全部面板。

专业方法原文见 [Web App Mindset](../../packages/skills-web-app/kits/web_app/mindset.md) 与 [Bundle 挂载清单](../../packages/skills-web-app/kits/web_app/kit.yaml)；内容依赖和分发说明见[内容包 README](../../packages/skills-web-app/README.md)。

## 决策与运筹建模：把业务经验带进模型（内部验证）

本节保留非 Web 领域的方法示例。Decision Modeling Kit 暂仅内部验证，不随默认产品
交付，不从公开源码导出，也不推荐对外安装既有 npm 包。内部源码与将来独立安装的
能力保留；以下教学内容不构成当前公开安装入口或交付承诺。

例如，一个上门服务团队要把工单分配给技术人员。工单地点、可服务时段、技能要求和工作量可能已在表格里；某些客户的特殊要求、实际工时和团队的公平取舍，需要懂业务的人补充。

你负责解释这些业务含义并判断方案，Agent 帮助梳理、建模和解读。开始时不需要懂数学符号，可以先用少量人员和工单说明情况。

### 面板分别帮助你判断什么

| 设计维度 | Bundle | 你需要理解或确认的内容 |
| --- | --- | --- |
| 问题与边界 | `decision_brief` | 要决定什么、什么是好方案、哪些事情暂不考虑 |
| 对象与关系 | `decision_objects` | 人员、工单、技能等业务对象，以及它们如何联系 |
| 输入数据 | `decision_data` | 字段含义、单位、来源和样例值；哪些值已知、未知或暂作假设 |
| 约束与规则 | `decision_rules` | 必须遵守的条件、可协商的偏好，以及业务例外 |
| 目标与评价 | `decision_objectives` | 减少等待、控制路程、公平分配等目标如何取舍 |
| 数学模型与解释 | `decision_model` | 业务条件怎样对应变量、目标和公式，模型省略或假设了什么 |
| 求解结果与解释 | `decision_results` | 实际运行是否得到可用结果，方案含义、瓶颈与限制是什么 |
| What-if 实验与比较 | `decision_comparison` | 改变人员、时段或规则后，哪些指标变好，付出什么代价 |

前五类信息是模型的业务依据。建模、求解和比较过程中，可以返回任一部分修订；八个维度不等于必须依次走完的八步。

### 用小规模样例理解方法

在已获授权的内部验证环境中，可以用这样的请求检验方法：

```text
我们有三位技术人员和五张上门服务工单，要安排明天的工作。
先用明确标注的样例数据，帮我梳理技能、服务时段和工作量，
让我看懂需要哪些信息。没有依据的时长或路程请保留待确认。
我懂业务，但不懂优化建模；请解释每项规则怎样影响安排。
先不要求解，等我确认小问题表达正确后再继续。
```

用户已有表格时，把文件交给宿主 Agent。它按当前工具能力读取和整理，面板用于查看、核对和修改解析后的结构与样例；无需先寻找面板内的上传按钮。

样例通常来自真实数据的一小部分，或一个明确标为合成的小问题。先确认字段、规则和模型含义，再检验小规模结果；发现问题就修订，验证后再考虑更大数据。未知值不能悄悄补成零，也不能把假设当作实际记录。

### 有结果以后，再比较方案

Kit 不随内容包安装求解器。没有可用引擎时，可以继续完善业务定义和模型；实际求解使用宿主可访问、已获授权的现有工具。模型尚未运行或校验时，应保留相应状态。

有真实基线结果后，可以问：“如果明天多一位具备该技能的人，等待和工作量会怎样变化？”比较报告应区分预期与实测，说明改变了什么、使用哪份模型和数据。没有重算时不能把 AI 的推测写成新结果。内部验证时还需分别记录实际求解环境、工具版本与执行限制。

本节是内部方法说明；既有[非 Web 实测案例](non-web-kit-demo.md)中的历史决策澄清不等于这个工单案例已完成求解，也不改变当前内部验证状态。当前宿主和安装版本的验证范围见[预览状态](preview-status.md)。

## 继续使用，或定制适合自己的方法

在当前项目中修改面板，改变的是你的设计成果。希望为今后的项目改变引导、结果结构或面板时，再定制 Kit 或 Bundle：从[最小定制教程](custom-kit-tutorial.md)开始，操作与保存位置见 [Studio 指南](usage.md#6-studio查看定制和检验套件)，交给别人使用前按[分享指南](kit-sharing.md)检验。
