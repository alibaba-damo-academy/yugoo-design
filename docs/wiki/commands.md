# yugoo 命令参考

语构设计系统（Yugoo Design）的 `yugoo` 入口管理设计项目、套件和设计交接。本页列出当前共享实现的全部 **11 个规范子命令**。生成具体设计、打开面板、评估或审查由已安装技能及对应工具处理，不是额外的 `yugoo` 子命令。

首次使用见[开始使用](getting-started.md)，日常协作见[使用指南](usage.md)，实现职责见[共享项目入口契约](../design-command-agent-entry.md)。源码文档不会自动升级已安装插件；旧安装版以随包帮助为准。

## 各宿主怎样输入

| 宿主 | 用户入口 | 用法 |
| --- | --- | --- |
| DeepSeek Harness（DSH） | `/yugoo` | 可直接输入本页的斜杠命令 |
| Codex Desktop（macOS arm64） | 当前对话中已启用插件的 `yugoo` 技能或技能选择器 | 描述本页操作，由桌面适配器保持原会话绑定；不使用 CLI 的连接步骤 |
| Codex CLI | `$yugoo` 技能 | 调用技能并描述本页操作，由 Agent 使用共享项目工具 |
| Claude Code CLI、Qoder CLI | `/yugoo-design:yugoo` 技能 | 按原生技能入口描述操作，不假定支持 DSH 的命令解析器 |
| WorkBuddy、千问办公（QwenWork） | 已启用插件的 `yugoo` 技能 | 在主对话用自然语言提出相同操作 |

所有宿主都可以直接表达意图，例如“用 Yugoo Design 打开客户项目交付项目，显示当前套件和保存版本”。不需要自己拼会话 ID 或寻找 connection 文件。具体安装、重载和能力差异见[宿主兼容](hosts.md)。

## 语法和参数约定

DSH 的格式是 `/yugoo 子命令 参数`。`<参数>` 表示必填，`[参数]` 表示可选；输入时不带尖括号或方括号。子命令使用下表中的小写标识。

共享解析器将子命令后的**整段文本作为一个参数**，并去掉首尾空白；它不是 shell，不拆多个位置参数、不展开环境变量，也没有通用 `--force`、`--version` 或 `--project` 选项。名称和路径可以含空格，直接填写即可，不额外加 shell 引号。自然语言请求由 Agent 转成对应操作。

- `name`：显示名称，不是保存路径；新建时不能与已注册项目重名。
- `id`：项目列表中的完整项目 ID，不使用文档里的省略号或猜测短前缀。
- `path`：宿主进程可访问的**绝对本地路径**。Windows 用 `D:\Projects\...`，Linux/WSL 用 `/home/...` 等实际路径；不把两套路径混用，不写 `~` 代替展开后的路径。
- `kit`：当前可用套件的技术 ID，例如 `web_app`，不是展示名，也不是 `Bundle` 名。此参数没有单独的版本开关。
- `brief`：一整段可选的开发规格范围说明，不是输出文件参数。

## 全部命令一览

| 命令 | 参数 | 前提 | 结果 |
| --- | --- | --- | --- |
| `/yugoo` 或 `/yugoo help` | 无 | 无 | 显示帮助和当前选择 |
| `/yugoo new <name>` | 必填名称 | 可写项目目录 | 新建、登记并选中项目 |
| `/yugoo open <id\|name\|path>` | 必填 ID、唯一名称或绝对路径，三选一 | 项目存在且可校验 | 打开项目并绑定当前会话 |
| `/yugoo list` | 无 | 无 | 列出已注册项目，标明当前选择 |
| `/yugoo status` | 无 | 无 | 查看当前选择、Git 状态及可用的建议状态 |
| `/yugoo kit <kit>` | 必填套件 ID | 已选中项目、首次选择的套件可用 | 首次复制完整套件定义并记录来源；重复选择继续使用项目文件 |
| `/yugoo close` | 无 | 已选中项目 | 解除当前会话的项目选择，保留文件 |
| `/yugoo delete <id\|name>` | 必填完整 ID 或唯一名称 | 用户明确要求移除 | 移除登记，保留文件和 Git 历史 |
| `/yugoo migrate <path>` | 必填旧项目根目录绝对路径 | 来源含 `design_files/`，目标套件可用 | 新建迁移项目，继续校验与适配内容 |
| `/yugoo reconstruct <path>` | 必填材料文件、目录或代码仓库绝对路径 | 来源可读，不是设计项目 | 新建重建项目，由 Agent 继续提取并还原设计 |
| `/yugoo compose_spec [brief]` | 可选范围说明 | 已选中设计项目；实际写入须有明确开发工作区 | 准备交接，让 Agent 组装开发规格 |

`kit <kit>` 选择的是整个套件，不是单独替换一段提示词。没有参数的 `kit` 不用于列举套件，请让 Agent 显示可用套件，或在提供 Studio 的宿主中查看。

## help、list 和 status

```text
/yugoo
/yugoo help
/yugoo list
/yugoo status
```

`list` 显示名称、ID、根目录、已有套件及当前选择标记。`status` 显示选中项目和 Git 工作树是否干净、最近 checkpoint；建议运行信息取决于宿主接入。未选择项目时会提示创建或打开，不会自动把聊天工作目录当成设计项目。

这三个命令不生成设计、不评估分数、不刷新图谱，也不派发审查。想查当前 UST/KAG/GRA，可直接让 Agent 查看对应服务状态，见[使用指南](usage.md#3-处理建议)。

## new 新建项目

```text
/yugoo new 客户项目交付协作平台
```

新项目具有独立身份、文件目录和 Git 仓库，创建成功后成为当前选择。默认保存在当前操作系统 Documents 下的 `YuGoo/Projects`，显式配置的项目父目录优先；项目名用于生成带唯一标识的目录名，不能用 `new` 指定目标绝对路径。

创建项目本身不生成业务设计，也不保证已经选好 Kit。随后描述目标让 Agent 选择合适套件，或执行 `kit web_app`。若名称已被登记，先用 `list` 确认是要继续旧项目还是使用另一个名称，不重复创建同一项目。

## open 打开已有项目

```text
/yugoo open 客户项目交付协作平台
/yugoo open D:\Projects\design-team-delivery
```

按已登记 ID、唯一名称、绝对路径的顺序解析。路径必须指向完整、有效的设计项目；普通代码目录或仅有几份文档的目录不是可直接打开的项目。合法但未登记的项目可通过路径重新登记，所以 `delete` 后仍能用原路径打开。

重复打开当前项目不会重新生成内容。Companion 切换项目后，Agent 应按返回的项目根目录重新打开自己的面板；旧面板不自动变成新项目的面板。项目文件可跨会话继续，原会话的执行任务和连接不能借用。

## kit 选择套件

```text
/yugoo kit web_app
```

先 `new` 或 `open`。项目首次选择当前宿主实际提供的 Kit 时，命令校验套件，将完整 Kit 与挂载 Bundle 复制到项目的 `design_kit`，并记录内容来源。已有项目重复选择同名 Kit 时继续使用自己的文件，内容库更新或删除不改变它。项目源缺失或损坏时，按[项目内容更新与恢复](kit-sharing.md#更新与恢复项目内容)处理，不自动换成内容库新版。

`kit` 不是安装命令，不能用它下载一个不存在的套件，也没有 `kit web_app@latest` 这样的版本选择约定。已选 Kit 的项目不能靠再次执行此命令切换到另一身份。需要变更方法时，请 Agent 对比和修改项目内文件，保留定制与既有设计，并按普通校验和 Git 流程记录；不要通过手改来源版本伪装完成更新。

## close 和 delete

```text
/yugoo close
/yugoo delete 客户项目交付协作平台
```

`close` 只解除本会话选择，文件、Git 历史和未提交改动原样保留；工作树不干净时会提醒。没有当前项目时返回提示，不创建新项目。

`delete` 是**从列表移除**，不是删除目录。它只接收完整 ID 或唯一名称，不接收路径；移除当前项目时也解除当前选择。若需重新使用，执行 `open <原项目绝对路径>`。真正删除磁盘内容属于另一个明确操作，不是本命令的隐含步骤。

## migrate 迁移已有设计项目

```text
/yugoo migrate D:\Projects\old-studio-design
```

参数是包含 `design_files/` 的**旧项目根目录**，不是 `design_files/` 本身。来源目录保持只读，旧 Session 不重放；迁移结果写入新项目，原项目不会被替换。

先准备目标 Kit。Companion 要求当前已选项目具有可用 Kit；如尚无选择，先创建一个准备项目并选择套件，再执行迁移。DSH 依次尝试来源记录的 Kit（精确版本可用则优先，否则同名可用版本）、当前项目的 Kit、唯一已安装 Kit；仍无法确定时会报告缺失项。

命令只暂存所选套件能识别的 Bundle 文件，后续 Agent 逐项校验：能直接使用则发布，不能则按当前契约最小适配并报告失败项。**“迁移目标已创建”不等于所有内容已适配完成**。未知 Bundle、不支持的旧格式、缺失套件或资源不能保证自动迁移。它不复制旧 Git 历史、运行状态、缓存或历史评估，具体文件边界见[项目文件与版本管理](project-files.md)。

## reconstruct 从材料还原设计

```text
/yugoo reconstruct D:\Materials\studio-app
/yugoo reconstruct D:\Projects\studio-app
/yugoo reconstruct /data/product.md
```

可以指定代码仓库、材料目录或普通文件，目录内可有文档、截图与源码，不要求 Git。已有应用可用它补齐设计资料、梳理当前行为，随后在面板中继续讨论修改。输入若已是设计项目或含 `design_files/`，应改用 `migrate`。

命令创建并选中一个新项目，项目名从材料名称生成，冲突时添加后缀。Agent 随后选 Kit、读取相关证据，并将有依据的功能、流程、规则、数据或界面等内容还原为可编辑成果。**命令返回“项目已创建”不等于重建完成**；还需报告实际保存的成果、来源、检查范围与剩余缺口。

来源保持只读，不执行或修改产品代码，也不整仓复制或镜像。单文件输入只针对该文件；不能读取的格式、推断和未知项须说明，不将文档计划、截图或未接线代码想象成已实现功能。具体请求与结果检查见[重建指南](usage.md#5-从既有材料重建设计)。

## compose_spec 交给开发工作区

```text
/yugoo compose_spec 只组装客户修改请求与交期确认，写入当前开发工作区既有 specs
```

省略 `brief` 时使用当前对话中已明确的范围；目标代码工作区或范围不清楚时，Agent 会澄清。命令先返回所选设计项目、Kit、checkpoint 和组装指引，**此时还没有写出 Spec**。

Agent 读取相关已保存设计，在获准的代码工作区沿用既有 Spec Kit、OpenSpec、Kiro 等约定；没有既有约定时按 Spec Kit 的 `spec.md`、`plan.md`、`tasks.md` 组织。结果应回报实际文件路径、设计来源与未决事项，不复制全部设计文件，也不把设计项目目录当成默认代码工作区。组装 Spec 不等于授权编码，详见[设计到开发交接](../design-development-handoff.md)。

## 常见错误与下一步

| 提示或现象 | 处理 |
| --- | --- |
| 未知命令 | 查看 `/yugoo help`；不要把 npm 安装参数或其他宿主前缀套进来 |
| 缺少名称、路径或套件参数 | 按一览表补齐；无参数命令不要额外带参数 |
| 名称不唯一、找不到项目 | 先 `list`，使用完整 ID；未登记项目使用绝对路径 |
| 路径必须是绝对路径 | 使用当前宿主可访问的实际本地路径，展开 `~`，不要混用 Windows/WSL 路径 |
| 未选择项目 | 先 `new` 或 `open`，不是重新安装插件 |
| Kit 不可用或项目定义缺失 | 首次选择核对可用套件；已有项目核对 `design_kit`，旧格式恢复真实原内容，按分享/恢复指南处理 |
| 另一个项目命令仍在运行 | 等该次操作结束；不要并发创建/切换或盲删锁文件 |
| 命令成功但面板仍是旧项目 | 让 Agent 使用本次返回的项目重新打开面板，勿搜索或借用旧连接 |

开发者可从 [`parseDesignCommand` / `runDesignProjectCommand`](../../packages/core/src/design-project-adapter.ts)、[项目注册表](../../packages/core/src/design-project-registry.ts)及 [Companion 接线](../../packages/companion/src/project-commands.mjs)核对解析与行为。Agent 工具的 `action` 对应本页子命令，`argument` 对应整段参数；Companion 另外需要宿主提供的主会话身份，但这不是用户需要输入的命令参数。
