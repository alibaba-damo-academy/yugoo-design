# 使用指南

[English](usage.en.md) · 简体中文

在熟悉的智能体宿主（Agent Host）中提出目标，通过设计面板（Design Panel）查看和修改结果，再让 AI 基于已保存的设计继续。先完成[开始使用](getting-started.md)，各宿主入口见[兼容说明](hosts.md)。本页先介绍设计项目中的日常协作，再介绍设计工作室（Studio）的内容创作。

## 1. 选择项目与目标

DSH 可使用 `/yugoo new <name>`、`/yugoo open <id|name|path>` 和 `/yugoo status`；Companion 使用已安装的 `yugoo` 技能与项目操作入口。项目文件独立于聊天，可从其他会话继续打开。

项目入口为 `yugoo`，具体调用方式遵循宿主原生语法；查阅[宿主指南](hosts.md)选择适合当前插件版本的入口。

例如，在 DSH 新建项目可使用 `/yugoo new research-platform`；需要手动选择 Web App Kit 时，可使用 `/yugoo kit web_app`。其他宿主可直接说“使用 Yugoo Design 新建客户项目交付平台，选择 Web App Kit”。所有子命令、参数、前提和错误处理见[命令参考](commands.md)，宿主指令形式见[宿主指南](hosts.md)。

描述需要的结果，例如：

```text
请梳理客户项目交付平台的功能模块，并说明重要例外。
请调研同类产品并保留引用
请生成核心业务流程
请根据现有设计生成高保真页面原型
请把当前设计整合成一份 PRD
```

主 Agent 结合设计套件（Kit）的领域主提示词（Mindset）、当前目标和已有证据选择方法。已有明确目标时可以直接请求相应结果；还不清楚从哪里开始时，可以请它提出适合当前情况的设计活动，并说明各自能解决什么问题。无需先完成全部访谈或按清单运行所有设计技能包（Bundle）。

开始时不必准备完整需求。可以先说明实际情况、在意的结果和这轮边界，例如：

```text
我们用聊天沟通客户修改，经常说着说着就增加了交付内容。
先给我一个能讨论的修改处理流程，解释有哪些选择。
设计师可以整理意见，新增范围和交期由项目负责人确认。
这轮先不做合同收费和财务管理。
```

你提供业务背景和取舍，AI 用当前 Kit 的专业方法帮助展开。遇到无法回答的问题，可以要求先看一个例子、解释影响或采用可修改的暂定方案；尚未确认的信息应保留为未知或假设。

## 2. 查看并修改 Panel

在当前设计的 Panel 中查看结构、图表和 artifacts，修改可编辑字段并保存。Panel 和图中的详情表单操作同一份数据；实际控件与编辑能力由安装版的 Bundle/Panel 声明决定。

保存成功后，可以直接请求下一步设计，不需要每次关闭、重开来证明保存。首次验证或怀疑内容未保留时，再重新打开核对真实字段。校验错误、并发冲突或未完成的后续处理需要按界面诊断处理，不把一次点击当作保存成功。

例如，AI 展开功能模块面板后，你可以删掉第一版不需要的功能、修改优先级，再要求“根据已保存的范围，展开客户修改请求的流程”。在流程面板中继续讨论谁记录反馈、谁确认范围和交期。这个过程把讨论落实为可继续修改的成果，而不是每一轮都从聊天描述重新猜测。

反馈可以落在具体对象和实际影响上：

```text
这里把每项修改都交给负责人。我希望设计师能直接处理范围内的布局调整，
新增页面或业务能力才讨论范围。请调整这个分支，并检查已有规则是否需要修订。
```

面板中的直接修改适合表达确定的字段和关系；需要解释原因、比较方案或联动其他设计时，可以结合对话提出。希望 AI 看到的面板修改应先保存，再指明需要继续推敲的地方。

保存成功后，可以在原会话中继续推敲这些修改。如果 AI 没有继续，或仍引用旧内容，先查看原会话是否收到修改，再按[故障排查](troubleshooting.md)检查保存通知和后续处理。消息状态不明时先查看已有任务，避免重复提交。

## 3. 处理建议

Grounding、Reflection、Alignment 可以提出疑点、研究或澄清建议。查看、接受、拒绝或稍后处理按实际宿主入口执行。建议本身不修改设计文件；需要改设计时通过所属 Bundle 正常修订，澄清或研究也可以先在宿主对话中提问、搜索，或解释为何无需追加动作。

例如，允许设计师直接处理范围内修改后，审查可以提示你考虑这些修改对已承诺交期的影响。先看建议引用了哪些设计，再判断是修订、解释现有规则，还是暂不处理；不要仅凭建议文字把它当成已确认的新要求。完整情境见[客户项目交付教程](web-app-demo.md#4-用一条建议发现尚未想清楚的取舍)，审查视角和能力边界见[知识关联与审查](concepts.md#知识关联与审查)。

支持自主审查的安装版允许通过审查设置选择是否后台检查。关闭自主审查后仍可主动请求检查；具体入口和后台能力以[宿主兼容](hosts.md)为准。

后台不可用，或原生异步评审仍占用主对话时，先选择“关闭自动 GRA”或“本次在主对话同步评审”。同步方式会暂时占用对话，须经用户确认；未选择时不改策略、不运行评审，关闭自动 GRA 后仍可手动检查。各宿主版本的实际限制见[后台能力与评审降级](hosts.md#后台能力与评审降级)。

例如：“关闭自动评审，保留我手动检查的能力”；或“现在手动检查当前功能和流程，我接受这一次同步占用对话，先不要采纳建议”。先完成本轮计划中的设计修改，再评审这一版，避免刚审完就因改稿重新审查。

### 查看和更新 UST

清晰度评估（U/S/T）由 Agent 根据当前目标与实际设计证据判断，并记录分数和理由。它不是已执行 Bundle 的计数，也不是必须满分才能继续的门槛。

```text
请根据当前已保存设计更新 U/S/T，说明各维度的事实依据和最重要的缺口。
通过评估工具保存结果；不要为评分重新生成设计或启动 GRA。
```

最新成功记录在项目的 `design_records/clarity.json` 中，并由 Git 跟踪。报告失败时保留上一次结果，缺失表示尚未评估而不是零分；设计证据变化后可再次评估。输入未变时可以复用，不要求每次工具调用都重报。字段和版本机制见[项目文件](project-files.md#ust-具体记在哪里)。

### 查看 KAG 与索引状态

知识关联（KAG）帮助定位设计对象、关系与证据。在 DSH 中，点击对话顶部的「Yugoo设计」打开设计面板，再点击底部「关联图谱」（Related graph）；在 Companion 中，进入已连接项目的完整工作区，点击底部同一入口，它与「设计文件」「场景体验」并列。

入口需已选择项目且宿主提供图谱读取能力；单个 Panel 预览不显示完整工作区的底部切换。若当前入口没有图谱视图，可请 Agent 查询设计来源及关系，不必因此重建索引。打开图谱后结合节点详情和来源阅读，不把相似度连线或 Agent 的解释当作已确认业务关系。这是项目知识图谱，不是 Studio 中的 Bundle 关系图。

如果显示需要更新，可请 Agent“查看当前项目的图谱状态；已有匹配索引就复用，确实陈旧时刷新一次，并说明完成还是仅已受理”。`due` 表示待更新，不等于正在运行；失败或暂时不可用时仍可直接读设计文件。图谱状态与 GRA、UST 分别判断，具体状态见[排错说明](troubleshooting.md#kag-或主动审查没有结果)。

#### 从图中读回设计依据

先用「概览」找设计记录，再从节点详情局部展开需要阅读的内容；查看一条聚合连线时，可以展开关联两端，检查原始端点、文件位置和证据。全局展开适合查看整体结构，局部展开更便于集中判断一个问题。折叠后的线条可能汇集多条依据，数量增加不代表关系更可靠。

| 看到什么 | 怎样理解 |
| --- | --- |
| 包含或引用关系 | 用于定位内容层级或原文明确引用；沿来源回到设计文件核对 |
| 语义相似线 | 帮助发现可能相关的内容，不直接证明依赖、因果或业务冲突 |
| 支持、实现、约束、先后或矛盾等解释 | 分别检查关系含义、来源、方向、状态及两端证据；Agent 提出的解释仍需核实 |
| 孤立节点、未知关系或较多连线 | 不能仅据此判为设计缺陷、缺失关系或业务核心 |

通过搜索、筛选、缩放和局部展开缩小阅读范围；这些操作不修改设计事实。图谱有读取、索引和显示预算，出现部分覆盖提示时，当前画面不能证明未显示内容不存在。需要完整判断时，请 Agent 说明查询版本、筛选和分页范围，并回读相关设计文件。想改设计，应回到负责该内容的面板或 Bundle 修订；布局位置和候选关系不代替业务决定。

### 查看场景体验

在完整设计工作区的底部选择「场景体验」，把分散的流程、规则与界面放进一个具体情境中查看。例如：“客户临时追加一个页面，设计师如何判断影响，负责人在哪里确认安排？”

尚无体验时，点击「让 AI 推荐体验情境」；已有体验时，也可以通过「新增场景」提出新的情境。先和 AI 确定想体验什么、帮助判断哪个问题，再让它根据已保存设计生成体验。生成后，从场景目录选择内容，在「体验说明与设计依据」中查看来源和演示假设。

画面内操作只用于演示，切换后重置，不会直接修改设计文件。发现步骤、文案或规则不合适时，点击「在主对话讨论当前内容」，说明需要调整的地方，再通过相应设计面板修订。设计改变后，原体验仍可回看；出现过期提示时，可选择「按最新设计刷新」。这样，体验中的发现可以回到设计讨论，而不只停留在看原型。

### 决定下一步做什么

有用的下一步建议会说明：当前还缺什么、为什么会影响你的目标、这次行动能帮你看清什么。它可以是展开另一个面板、补充研究、比较方案，或返回已有设计修订。GRA 的一项发现可成为讨论依据；是否采用、如何落实，仍需结合当前请求判断。

如果宿主显示清晰度评估（U/S/T），结合理由和所对应的设计版本阅读。新增背景可能让分数下降，未使用的 Bundle 也不自动成为剩余工作。保存成功或审查完成，分别不等于已有最新评估；显示缺失、失败或旧版本时，不据旧分决定下一步，见[评估排查](troubleshooting.md#清晰度或下一步建议没有更新)。

你可以明确说“先修改这一点”“这个问题以后再看”“先给我草案”或“当前范围已经足够”。当设计已满足这轮用途，可以总结决定、保留未决事项并交接；应用设计可整理为 PRD，其他领域按自己的产物形式交付。

## 4. 管理与恢复

设计项目（Design Project）独立于聊天。DSH 的常用入口如下；Companion 使用其已安装 Skill 或共享项目工具执行同样的项目操作，不照搬 DSH 前缀。

| 想做什么 | DSH 当前入口 | 结果 |
| --- | --- | --- |
| 查看当前项目和套件 | `/yugoo status` | 检查当前会话选择 |
| 查看项目列表 | `/yugoo list` | 找到已有项目 |
| 选择设计套件 | `/yugoo kit <kit>` | 为项目首次选择 Kit；已有项目的内容更新按下方文件维护步骤处理 |
| 打开已有项目 | `/yugoo open <id\|name\|path>` | 将项目绑定到当前会话 |
| 关闭当前绑定 | `/yugoo close` | 保留项目文件，结束当前会话的选择 |
| 迁移已有设计项目 | `/yugoo migrate <path>` | 保留原件，在新项目中验证和适配 |
| 从文档、截图或源码还原 | `/yugoo reconstruct <path>` | 原材料只读，结果进入新设计项目 |

新建项目默认位于当前操作系统 Documents 下的 `YuGoo/Projects`；显式配置的路径优先，已有项目不会自动搬迁。WSL 使用 Linux 用户目录，不自动转向 Windows 的 Documents。项目 Git checkpoint 记录设计变更，关闭会话不删除这些记录。

在 `0.2.3` 发行版中，项目首次选择 Kit 时，会将完整 Kit 与挂载的 Bundle 文件复制到项目的 `design_kit/kit` 和 `design_kit/bundles`。之后，Agent、面板和校验使用项目自己的文件；内容库中的修改或删除不会改变已有项目。要使用库中的新方法，请 Agent 对比文件、说明差异并保留项目定制，再通过既有校验、保存和 Git 记录修改。旧版项目按其对应的内容恢复说明处理。

项目操作中的 `delete` 移除注册记录，保留实际项目文件；不要把它当作文件删除或清空目录。项目内容缺失，或旧格式项目无法找到原 Kit/Bundle 时，按[更新与原件恢复](kit-sharing.md#更新与恢复项目内容)处理，不把新版库内容冒充原件。文件布局、备份、移动和迁移边界见[项目文件与版本管理](project-files.md)，完整参数见[命令参考](commands.md)。

可以在对话中请求“比较这次保存前后的修改”“说明这条规则什么时候改变”或“读取这个 checkpoint 的设计并与当前版本比较”。Agent 使用只读 Git 查询定位依据，不需要复制全部历史，也不因查看旧版本就自动回滚当前设计。撤销修改是另一个需要明确范围的操作。

## 5. 从既有材料重建设计

接手陌生代码仓库、补齐既有应用的设计资料或准备改版时，可以先把“当前怎样工作”整理为可查看、可修订的设计。重建得到的是独立设计项目中的成果，方便你和 AI 对照实现、理解影响，再讨论下一轮改动。

有两种不同输入，不需要把旧设计文件复制成普通材料来绕路：

- **迁移设计项目**：已有 Yugoo 的 `design_files/`，用 `migrate <旧项目根目录>`。原件保留，目标 Kit 可识别的内容进入新项目，再校验并做必要适配。
- **从材料还原设计**：已有文档、截图或源码，用 `reconstruct <材料绝对路径>`。Agent 读取材料证据，生成新的设计成果；不是复制旧项目，也不是按想象重做产品。

例如，在 DeepSeek Harness 中：

```text
/yugoo reconstruct /data/product-materials
```

在 Companion 宿主中可直接请求：

```text
请用 Yugoo Design 从 D:\Materials\studio-app 还原现有应用设计。
材料保持只读；先了解真实入口和行为，选择合适的 Kit，
只还原有证据且与本次目标相关的设计，不运行所有 Bundle。
保留现有视觉和素材，区分观察到的事实、推断与未知。
完成后给我可编辑面板，并说明覆盖范围和无法确认的部分。
```

目录可以混合文档、截图与代码，也可以指定单个文件，不要求 Git。材料格式能否读取取决于宿主；不支持的格式需明确转换。截图不能证明后台规则，文档中的计划不能证明实现已存在。

### 从代码仓库开始

把仓库根目录作为材料路径；只关心某个子系统或用户流程时，一并说明范围。例如，在已安装的 `yugoo` 入口请求：

```text
请从 D:\Projects\studio-app 重建现有应用的设计，
本轮聚焦客户提交修改、设计师判断影响、负责人确认安排这条链。
对照真实入口、相关处理与数据读写，整理功能、流程和业务规则；
有实际界面时保留其布局和素材，给我可核对、可编辑的设计成果。
区分代码支持的行为、文档中的意图与未知项，不执行或修改原产品代码。
```

DSH 也可输入 `/yugoo reconstruct D:\Projects\studio-app`，再说明本轮范围。路径要替换为当前宿主可访问的绝对路径；源码目录不是供 `open` 打开的设计项目。

命令先创建并选中新项目，随后由 Agent 了解产品、选择合适 Kit 并继续重建。Agent 围绕相关入口查看处理逻辑、数据、权限和界面等证据，选择有实际内容的 Bundle，结果按正常校验和保存流程进入新项目。源码中的目录、依赖或测试文件本身不能证明某项功能已接通；未检查的区域也不能直接判作不存在。

原仓库保持只读。重建不整仓复制、建立源码镜像或执行其中的代码；所需原始视觉素材可按所属成果复用。只提供一个文件时，读取范围就是该文件，不自动扩展到相邻目录。运行后才知道的行为、无法读取的格式或无法忠实表达的界面，应在结果中说明。

### 检查结果并继续设计

请 Agent 回报已保存的设计维度与文件、对应源码位置、实际检查范围，以及尚存偏差、未知和未检查项。可以直接请求：“说明客户修改请求的每个关键入口对应哪项设计，还有哪些部分没有核实。”仅创建了项目、列出执行计划或生成页面目录，都不等于已经还原了相应成果。

对照原材料检查关键入口、流程、页面和跨 Bundle 引用，再在普通面板中修改并保存。格式校验通过不等于已浏览器验证或完全忠实还原；没有运行比对时，不应声称交互与原应用完全一致。确认当前行为后，再明确提出希望改变的规则或体验，继续在同一设计项目中迭代；修改设计不自动修改原仓库。

完整参数与迁移前提见[命令参考](commands.md)，文件和历史如何处理见[项目文件管理](project-files.md)。素材复制、预览资源、可选 KAG 与收尾核对的技术约定集中在[还原执行说明](../design-command-agent-entry.md#reconstruction-execution-notes)。

## 6. Studio：查看、定制和检验套件

Studio 管理构思时使用的方法和面板，日常 Design Panel 编辑的是你的设计成果。Companion 可从设置打开 Studio，在独立浏览器页中沿用当前服务连接；DSH 使用宿主提供的 Studio 入口。

**适用版本：** 以下原地编辑、源码导入和项目自带内容的说明对应 `0.2.3` 发行版。Studio 完整创作流程的验证仍在进行；使用前核对[宿主指南](hosts.md)和[发行状态](preview-status.md)，了解实测范围与已知问题。旧版入口按其对应说明操作。

### 查看套件与技能包

从左侧“套件”进入 Kit，阅读 Mindset 并查看已挂载的 Bundle 身份。“原始文件”提供实际文件树，可以查看完整 frontmatter、挂载投影和参考资源。阅读视图方便浏览，原始视图保留文件内容。

从“技能包”查找 Bundle，查看方法、输出契约、schema、validation、语言资源和面板声明；详情也显示哪些 Kit 引用了它。本地 Kit 的挂载读取该 Bundle 身份当前保存的内容。只复制 Kit 会保留这些引用；需要独立修改某个 Bundle 时，再复制它并调整挂载。

### 编辑与独立定制

选择 Kit 或 Bundle 后点击“编辑”，打开同一身份的当前内容。需要保留原方法并另做一套方案时，使用“复制”创建独立身份；支持从空白开始的入口也可使用“新建 Kit”或“新建 Bundle”。

1. 在创作工作区的“原始文件”中编辑，检查差异并明确保存。保存保留当前身份，不需要发布本地版本或重新挂载。
2. 切换文件或离开前处理未保存内容；刷新后重新打开同一对象，检查已保存文本。文件尚未完整时也可以先保存；加载或预览会指出它实际需要补全的定义。
3. Kit 的“挂载管理”按 Bundle 身份组织能力，并读取其当前内容。需要独立定制某项方法或面板时，先复制相应 Bundle，再让 Kit 挂载该副本。来源版本用于追溯，不是每次保存必须更新的版本号。
4. 用样例预览检查改动，再在独立新项目中选择准备好的 Kit，核对项目中的完整方法与资源，并生成、编辑、保存和重开成果。已有项目继续使用自己的文件；要更新它，请 Agent 对比库与项目的 `design_kit`，保留定制，并在宿主允许写入的范围内按普通校验和 Git 流程修改。具体见[分享与项目维护](kit-sharing.md)。

标题处的重命名修改展示名称，不改变 Kit/Bundle 的技术身份。删除内容会检查 Bundle 引用，并将所选内容移到系统回收站；恢复按系统提供的入口处理。npm 发包、运行时组件发行及 Design Files 的保存发布仍按各自流程进行。

### 预览与试运行

| 操作 | 适合检查什么 | 保存与执行的含义 |
| --- | --- | --- |
| 面板预览 | 用 Bundle 样例检查布局、字段与声明 | 使用隔离样例，不启动模型，也不修改设计项目 |
| 编辑 Panel YAML 后预览 | 检查声明式 UI 改动及诊断 | 保存方法源码与样例交互是两件事 |
| 原生试运行 | 检查方法能否生成结果，以及结果面板 | 连接检查通过后向宿主发起真实任务，使用独立测试项目 |
| 日常 Design Panel 保存 | 修改当前项目的设计成果 | 经过项目校验与版本记录，供后续构思使用 |

Bundle 的“面板预览”优先读取其 `reference/preview.json`；没有可用样例时会显示诊断，不能把空界面当成完整体验。声明式面板可以编辑 YAML；native 面板由 Provider 实现，不提供可编辑的 `panel.yaml`。

试运行从 Bundle 标题处发起。先保存希望测试的源码，试运行读取这次保存的内容。首次可由原生 Agent 准备具体合成输入并执行；你也可以修改测试输入后明确重新运行，每次保留独立结果和原始输入。排队或连接可达不代表任务完成，未知执行状态不应当成成功，也不应重复启动。

试运行面板中的“演示保存”和“撤销修改”只演示当前浏览器的已保存界面状态，不发布设计文件或通知 Agent 继续；刷新会恢复真实生成结果。要验证耐久保存和续作，仍需在正常设计项目中完成操作。

### 组件与分享

支持“面板组件库”的安装版可查询同版本的声明式组件，查看合成示例并复制完整声明。组件库用于选型和学习；新组件仍需共享运行时注册与发行，不能在此安装任意可执行 UI。

Studio 可作为内容维护时的可视化工作台：查看样例、操作面板、指出表达或交互问题，再修改并重新查看。支持宿主对话创作的版本可把当前对象和请求发送给原宿主 Agent，在同一源码与预览中检查修改建议，再由你决定是否保存。没有该接线时，可由开发 Agent 在独立作者源维护完整方法、数据契约和面板，再回到 Studio 检查。作者流程见[扩展开发](extending.md#结合-studio-维护内容)。

在现有“导入”入口选择源码 ZIP、文件夹或单个 `SKILL.md`。Bundle 需要方法文件；Kit 需要 `mindset.md` 和 `kit.yaml`。导入保留原文件并创建独立身份，其他辅助定义缺失或尚未完整时，可在已有编辑器继续补全。旧归档 JSON 也可解析后通过同一源码入口导入。格式或文件完整性有问题时查看具体诊断；取消选择不改变内容。独立 Bundle 仍需明确挂载到 Kit。导入不会执行脚本、授予执行信任或改变已有项目。

导出前保存希望交付的内容，再从对象菜单选择“导出”，下载当前源码 ZIP；Kit 包含已挂载 Bundle 的完整文件与资源，未完成的方法也可以交给协作者继续修改。来源与许可证是可选说明，文件中已有的 LICENSE、NOTICE 和署名仍须保留。归档格式、依赖与接收者检查见[分享指南](kit-sharing.md#通过-studio-内容归档分享)。

维护 Studio 集成时，可进一步阅读 [Studio domain](../../packages/studio/README.md) 与 [Studio UI](../../packages/studio-ui/README.md)。设计成果交给后续实现时，使用[设计到开发交接](../design-development-handoff.md)。
