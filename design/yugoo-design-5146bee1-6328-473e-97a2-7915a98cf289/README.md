# 语构设计系统（Yugoo Design）自身设计

这个项目整理语构设计系统自身的能力、设计规则、界面基础和原生 Agent 协作职责。产品在用户既有的 Agent Host 内支持持续的设计理解、人工改写和交接；项目文件承载设计，聊天不是唯一存储位置。

这些资料是**对已有产品的设计归档**。按已采用的 Web App Kit 字段和规范，把已有源码契约、维护文档和明确用户决定整理为可阅读、可修订的设计资料。没有运行插件、设计会话或 reconstruct 模式，也没有把源码存在当作所有 Host 已通过验收。

资料沿用现有字段与备注，未修改项目或上游 schema，也未新增 Kit。Host/Agent 的执行职责没有硬套为多用户 RBAC；没有需要额外维护的用户角色，故不人为填满角色权限面板。页面、流程和完整视觉预览也没有为凑齐 Bundle 而生成。

## 资料含义与边界

- 规范基础来自开发仓的架构基线、Panel UIUX 规范、项目与知识生命周期说明、当前共享实现及明确用户反馈。各记录在既有说明或备注中保留相关来源；工程与运行协议继续由对应的架构、包说明和作者契约维护。
- 普通操作的 16px 图标 / 32px 点击目标是确认后的共享修正；不将它推广到身份图标、状态占位或所有画布资产。色值记录共享样式的无 Host 覆盖基准，实际界面仍继承 Host 的语义 token 和已解析主题。
- 风格文件当前只整理结构化规范，没有生成 `DESIGN.md`、`tokens.css` 或 HTML 预览。因此它通过的是 schema 与状态规则，不能称为一次已完成的 Style Bundle 交付。其缺少完整产物的诊断保留在工作记录。
- 没有生成 U/S/T、G/R/A、KAG 图谱或 `design_records/knowledge/archive.json`。未来真实流程产生的中立知识归档应随项目保留；Ladybug 数据库和向量索引属于外部本机缓存，不能替代关系、提议及人的决定归档。
- 这些记录已完成首轮内容审阅。开发时按任务读取相关功能、规则、风格与验收条件，并核对对应技术契约及实际实现；已有工程与运行协议不会因这份设计归档自动失效。

## 维护与源码协同

项目身份由 `project.json` 管理；本项目采用 `web_app` 1.2 的完整项目自有定义。上游方法后续更新不会自动替换这里的文件，也不是修订本地设计的前置条件。

项目自己的 `.git` 记录本地设计版本。母开发仓若携带设计资料，应跟踪实际普通文件，而非只保存一个嵌套仓库指针；公开同步仍使用既有固定源码导出与分类规则。源码快照没有携带子仓 `.git`，接收方需要通过普通 Git 初始化建立本地项目历史后再打开；不能声称还原了未携带的旧子仓历史或本机执行状态。

阅读或修改这些资料不授予代码发布、安装插件、连接模型、改变凭据或执行未授权任务的权限。具体开发任务沿已有工程原则与实际用户授权进行。

项目的 Bundle 成员及顺序由 `design_kit/kit/kit.yaml` 维护，模型目录由运行时生成；Mindset 只保留领域方法，不重复手工维护清单。
