# 回环交付：Web App 全面板审阅样例

[English](README.en.md)

这组语构设计系统（Yugoo Design）样例用于逐项阅读和修改 Web App Kit 的全部 15 个面板（Panel）。[中文来源](zh-CN/)与[英文来源](en-US/)围绕同一个合成业务：六人设计工作室在周五交付前收到客户追加反馈，需要区分原范围内的小改、新增范围、负责人承诺与通知送达。

两份内容使用对应的记录编号、关系和顺序。它们提供多条记录、长说明、未答问题、多选、附件、折叠内容、图形与详情，以及可读的专业产物，便于审阅真实内容下的面板细节。数量是本样例的覆盖情况，不是其他设计项目必须达到的门槛。

## 先迁移为自己的工作项目

仓库中的两份来源不含 `.git`，供迁移读取，不能直接用 `open` 打开。请保留原件，把所选语言的整个目录复制到仓库外尚未使用的位置。例如，在仓库根目录执行：

```bash
mkdir -p "$HOME/Documents/YugooExamples"
cp -R examples/web-app-panel-review/zh-CN "$HOME/Documents/YugooExamples/loopline-review-zh"
cp -R examples/web-app-panel-review/en-US "$HOME/Documents/YugooExamples/loopline-review-en"
```

也可用文件管理器复制。若目标已存在，请另选新目录，避免覆盖自己的修改。

按[安装指南](../../docs/wiki/getting-started.md)启用插件和当前 Web App Kit。先选定一个使用该 Kit 的准备项目，再将副本的绝对路径交给宿主，分别迁移两份来源。DSH 的入口示例：

```text
/yugoo migrate /absolute/path/to/loopline-review-zh
```

在 Codex 等原生宿主中，可以直接提出：

```text
请使用 Yugoo Design，把这个目录迁移为独立的面板审阅项目：
/absolute/path/to/loopline-review-zh
先确认当前已选项目使用当前 Web App Kit；若尚未选择，先创建准备项目并选择该 Kit。
保留来源原件，读取其中全部设计文件与产物。不要生成模型执行记录或评估结果。
迁移完成后打开新项目，从智能提问面板开始。
```

迁移使用当前已选项目的 Kit，建立新项目的身份、版本记录与项目自有定义；它不会复制来源的 Git 历史或评估记录。迁移后用返回的新项目编号或绝对路径 `open`，再迁移另一种语言。两份工作项目各自保存修改，切换宿主界面语言与切换项目内容语言也是两个操作。审阅时，中文来源配合宿主中文界面，英文来源配合宿主 English 界面；界面控件跟随宿主语言，已保存的业务事实不会自动翻译。已有两份独立工作项目时直接打开对应项目，不必重新迁移，也不新增项目语言属性。详见[项目命令](../../docs/wiki/commands.md)和[使用指南](../../docs/wiki/usage.md)。

流程产物使用布局修订 13。若现有 Kit 的校验器不支持此修订，请更新到支持它的版本，或按[开发指南](../../docs/wiki/development.md)使用当前源码；不要修改 BPMN 修订标记或 `project.json` 版本来绕过校验。

## 15 个面板的阅读位置

以下路径均相对所选语言目录中的 `design_files/`；各目录下同名 JSON 是该面板的规范数据。图形和详情编辑同一份数据。

| 面板 / Bundle | 已准备的内容 | 建议审阅路径 |
| --- | --- | --- |
| 智能提问 `smart_questions` | 两轮、14 个问题，含两个固定配置、Q-010 未答、Q-012 多选及 Q-002 Markdown 附件 | 展开长回答，查看附件，编辑多选与说明，滚动到第二轮末尾 |
| 调研 `research` | 两轮、6 个方向，各有 Markdown 分析与 HTML 结论 | 切换轮次和方向，阅读发现与结论，区分合成分析和外部查证 |
| 功能模块 `function_modules` | F-001～008，六组，包含已否决方案与多层行为、输入、输出、边界和异常 | 展开 F-002、F-004 的完整详情，修改长说明，再回到功能列表 |
| AI 能力 `ai_agent_capabilities` | 2 个 Agent、3 个 Skill、3 个工具、2 份知识资源、1 个模型来源声明 | 从 A-001 跟随协作与工具引用，阅读方法正文，核对人工采用与授权边界 |
| 业务流程 `flow_design` | P-001 新增范围确认与退回；P-002 负责人核对后重试同一通知，均有实际 BPMN | 切换流程，缩放与适配画布，查看职责、分支及退回路径 |
| 视觉风格 `design_style` | 颜色、字体、品牌、图标与交互模式；`DESIGN.md`、`tokens.css`、`preview.html` | 阅读规范与实际预览，核对长文字、状态反馈和表单层级 |
| 业务数据 `business_data` | 7 个对象、63 个字段、11 个状态、8 条关系 | 从 O-003 图形进入详情，滚动到字段末尾，再查看决定与投递的关系 |
| 业务规则 `business_rules` | BR-001～008，含补充、范围升级、明确决定、投递分离与隔离 | 比较条件和结果，编辑一条规则后核对其编号与顺序 |
| 角色权限 `role_access` | 4 个角色、8 条策略、1 条继承关系 | 读 R-LEAD → R-DESIGNER 的继承，再核对附带条件的禁止项 |
| 外部集成 `integration_design` | 附件、通知、身份三个设计；只有密钥用途声明 | 展开连接与密钥条目，核对失败恢复；地址为无效示例域名 |
| 通知设计 `notification_design` | 6 条通知，含接收人、渠道、正文与行动入口 | 对照 N-005 与 P-002，区分决定保存、回执未知和再次投递 |
| 质量与验收 `quality_acceptance` | 10 条可观察标准，含恢复、权限与窄屏阅读 | 读条件、通过标准和检查方式；这些是设计标准，不是测试结果 |
| 页面设计 `page_design` | PG-001～005、15 条连接、5 份完整 HTML；收件箱 18 行、历史 12 行 | 页面地图 → 详情 → 原型；沿列表、详情、负责人确认与历史返回，检查滚动和上下文 |
| PRD 整合 `web_app_prd_assembly` | `prd.html`，含完整功能规格、对象与规则表、所属脚本生成的图形与页面快照 | 读一条跨面板决策链，滚动至文末，核对图文邻接与来源 |
| 自由白板 `whiteboard` | WB-001 反馈与承诺边界、WB-002 AI 建议交接，两份原生 Excalidraw 场景 | 切换白板，缩放并查看文字、形状与连线，修改工作副本后重开 |

## 一条连贯的审阅路径

先读 Q-003、Q-005、Q-007 和未答的 Q-010，理解工作室怎样区分请求、承诺与投递。沿 F-002 → BR-003 → P-001 → PG-003 阅读新增范围判断；再沿 BR-006 → P-002 → N-005 查看投递失败后的恢复。R-LEAD 的明确授权、O-005 的决定和 O-006 的投递记录应与这两条路径对应。

在工作副本里修改 F-002 的长说明并保存，切到其他面板再返回，重开项目后核对修改仍在。接着从业务数据图形进入 O-003 详情，读到最后一个字段，返回图形查看关系；页面地图也应能从选中记录到详情并完整滚动。对编辑尝试一次取消，确认原内容保留，再完成一次保存。添加与删除操作请只在新建的临时条目上练习。

页面 HTML 是提议产品的原型，不是 Yugoo Design 自身的面板。原型中的搜索和提交反馈仅在浏览器中演示；没有业务后端、通知服务或真实成员变更。检查 Panel 保存、跨面板返回和重开时，请操作宿主中的规范设计字段。

这些设计展示同一协作旅程的不同阶段与可能决定，并非同一时刻的业务数据库快照。收件箱只有 FB-042 提供了对应详情路径；其他反馈用于阅读和筛选，未把不同编号都链接到同一条详情。

专业产物可独立阅读：调研 Markdown/HTML、流程 BPMN、风格规范与预览、页面 HTML、整合 PRD，以及原生白板文件都随来源提供。PRD 是这些设计的整合投影；修改事实时，先改所属面板，再更新 PRD。

## 语言对应与已知边界

中文与英文中的 F、BR、O、R、P、PG 等业务编号及引用一一对应，项目身份分别独立。自然语言、图形标签、页面与文档内容按语言准备；附件及调研内容的校验摘要因实际字节不同而不同，不能互换。

Flow 内建角色保持稳定编号 `System`，显示名按内容语言分别为“系统”和“System”。参与者与 BPMN 泳道复用角色表中的实际显示名，系统和人工活动的职责校验不变。修订流程时向文件校验器传入当前规范角色表；不要仅改显示名而留下不一致的参与者或泳道。

PRD 生成器沿用文档已有的 `<html lang>`，为功能范围图、页面关系图、导航图例及空状态提供中英文固定文字；没有声明语言的旧文档保留中文默认值。源业务名称与正文仍由各自内容所有者维护，图示从这些来源重新投影。样例和脚本检查不代表所有宿主界面、原生 Agent、保存重开或安装包已通过完整验收；这些边界仍需实际流程验证。

## 内容来源与使用范围

业务场景、例值、分析和标准均为人工准备的合成审阅材料。P-001 的流程结构沿用现有交付协作示例并保留署名；其他内容围绕本场景准备。这里没有真实客户资料、外部调研查证、模型调用、已发送通知、清晰度评估（UST）、关联图谱（KAG）或设计建议（GRA）结果。需要这些能力时，应在自己的工作项目中经正常宿主流程重新执行。

`project.json` 与 `design_files/` 保留可迁移设计；不包含宿主凭据、运行环境、历史评估或假造执行记录。AI 能力面板的提示词、Skill 和工具是待实现应用的设计内容，不会在阅读样例时安装或调用。样例随附 [Apache-2.0 许可](zh-CN/LICENSE)与[署名说明](zh-CN/NOTICE)，英文目录保留对应文件。
